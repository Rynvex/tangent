## 0. 直接貼給 Claude Design 的說明

你是 Tangent 的產品設計師。Tangent 是一個「可以分岔的 AI 對話」：聊天時可以從任何一則訊息岔出一條支線，
在支線裡把一件事問清楚，再帶著一張結論卡回到主線。它要解決三個痛點：**聊天太發散、token 太貴、AI 記不住重點**。

請為它做一套互動原型。這是全新的設計，沒有舊版要沿用，但有幾個硬性條件：

1. **主體是線性的對話**，樹狀圖是輔助。使用者大部分時間在閱讀與輸入，不要把首頁做成畫布。
2. **元件要能嵌進別的 app**：同一套元件會放進其他產品的側欄（約 420px 寬）。所有顏色、字級、圓角只能用 `--tg-*` 語意 token
   （附件 `styles.css` 是目前的命名，請沿用，新增的照同樣方式命名），並示範換一套宿主主題後仍然成立。
3. **功能可以關**：除了核心以外，每個功能都可能被宿主關掉（§6）。功能全關時介面不能有空洞，全開時不能擁擠。
4. **語言**：繁體中文為主；provider、model、token、Markdown 等專有名詞保留英文。用語請照 §3。
5. **圖示**只用 lucide 線條圖示；不要插畫、吉祥物、表情符號、遊戲化元素（等級、成就、連續天數）、行銷頁式大標題與漸層。
6. **字體**須可自架（OFL 等開源授權），中文要有對應字體。
7. **無障礙**：WCAG AA 對比、鍵盤可操作、清楚的 focus 樣式、尊重「減少動態效果」。
8. **假資料**用 §8 的情境，不要 lorem ipsum。

請先回答 §9 的設計問題（每題給建議與理由，必要時並排兩案），再開始畫。畫面依 §5 的編號製作，交付物見 §11。
優先順序：**A 階段（核心）要完整、細緻**；B 階段要完整；C、D 階段可以較粗，但要畫出主要畫面與元件，讓整體架構容得下它們。

## 1. 產品與使用者

**使用者**：拿 AI 來思考、研究、學習、做決定的人（工程師、研究者、學生、PM）。對話常常很長，會不斷冒出旁支問題。

**現在的痛點**
- 問一個旁支問題，主線就被打斷，回頭時忘了剛才在談什麼，AI 也被岔題帶偏。
- 對話越長，AI 越容易忘記前面定下的事，而且每一輪都把整段歷史送出去，越來越貴。
- 討論過的結論散落在幾百則訊息裡，下次開新對話又要重講一次。

**Tangent 的做法**：岔出去 → 問清楚 → 帶著結論回來；每條支線都要有收尾；送給 AI 的只有「需要的部分」；
重要的事寫進紀要與記憶，跨對話保留。

## 2. 設計原則（來自研究，請轉化成介面行為）

| 原則 | 依據 | 介面上的意思 |
|---|---|---|
| 每個岔題都要有收尾 | 未完成的事會持續佔用注意力（Zeigarnik；Masicampo & Baumeister 2011：訂好計畫就能放下） | 開著的支線、停車場的念頭隨時看得到數量；結束支線時一定留下「收尾」；停車只要一鍵 |
| 回到主線時要能立刻接上 | 切換工作後的注意力殘留（Leroy 2009） | 回主線時清楚顯示「你剛才在哪、帶回了什麼」；結論卡是主線裡最顯眼的訊息之一 |
| 少送一點，AI 反而更準 | 多輪對話平均掉 39%（Laban et al. 2025）；輸入越長越不可靠（Chroma 2025） | 讓人看得到這一輪送出什麼、花多少 token；可以預覽；遠處的支線只送一句結論 |
| 近的詳細、遠的概括 | 魚眼視圖（Furnas 1986） | 大綱與地圖：目前路徑展開、其他收合成一句收尾 |
| 結構化的討論 | XMind 的摘要、外框、關聯線、浮動主題；IBIS 論證地圖 | 地圖上的群組外框、關聯線、節點類型；停車場就是浮動主題 |
| AI 的提議要被「審」 | 使用者要保有判斷 | AI 草稿都以「待你確認」呈現；不要只有「下一步」按鈕 |
| 不打斷心流 | 心流需要清楚目標與不被打擾 | AI 建議永不彈窗、不搶 focus；每輪最多一個；有集中的建議匣；對話有一句目標 |

## 3. 名詞與用語

| 用語 | 意思 | 程式名稱 |
|---|---|---|
| 對話 | 一整棵樹（主線 + 所有支線） | root line |
| 主線 | 對話的根 | main line |
| 支線 | 從某一則訊息（分岔點）岔出去的子對話，有一句「目的」 | branch |
| 支線種類 | **順口問**（一問一答，答完自動結束，7 天後清除）、**查證**（多輪，帶結論回來）、**另一條路**（試別的方向，可能取代主線） | aside / investigate / alternative |
| 支線狀態 | 進行中、已帶回、未帶回、已升為主線 | open / merged / discarded / promoted |
| 背景 | 開支線時從主線整理給支線的脈絡（主線摘要、最後幾則、選取的文字） | pack |
| 結論卡 | 支線帶回主線的卡片，使用者確認後才出現在主線，下一輪才送給 AI | branch card |
| 收尾 | 每條結束的支線留下的一句話：**結論 / 決定 / 答案 / 死路 / 待續** | leaf |
| 紀要 | 整棵對話共用的一頁重點：已決定、已確認的事實、待確認、待辦 | notes |
| 章節 | 依話題或閒置時間自動分段，也可以手動加里程碑 | chapters |
| 停車場 | 一鍵存下的念頭（種子），不花 token，之後再展開、記進紀要或丟掉 | parking / seed |
| 獨立 | 把支線（或某一點之後）變成一個新的對話，保留背景與連結 | spinoff |
| 群組 | 把幾條相近的支線圈起來，用一段共同摘要代表它們 | group |
| 關聯 | 兩個節點之間的連線與說明 | relation |
| 目標 | 一句話描述這段對話要達成什麼 | goal |
| 記憶 | 跨對話保留的事實、決定、偏好、教訓，都有出處 | memory |
| 建議 | AI 提出、等你決定的事（開支線、升為主線、合併、折疊…） | suggestion |
| 折疊 | 把一段訊息收成一段摘要，送給 AI 時只送摘要 | fold |
| 名詞表 | 這篇對話裡問過、已經懂的名詞與各自的解釋；AI 每一輪只看到名詞（不看解釋），就不會重講 | glossary |
| 名詞 | 名詞表裡的一筆：名詞本身（一行，最多 60 字）加一段解釋 | term |

## 4. 版面架構（請提案，以下是起點）

- **左：對話清單**（約 280px，可收合）：搜尋、依時間分組、封存區。每列：標題、最後活動時間、進行中支線數、未讀或等待你的標記。
- **中：對話**（彈性寬度，訊息閱讀寬度約 680–760px）：
  - 頂端：路徑麵包屑（主線 › 支線 › 子支線）、目標（C 階段）、token 計量、動作選單。
  - 訊息列表：使用者、AI、系統（結論卡、標記）三種訊息；分岔點標示；章節分隔。
  - 輸入框：送出、停止、預覽這一輪、開支線、停車。
- **右：側欄**（約 360px，可收合、可拉寬）：大綱、地圖、紀要、章節、停車場、建議、記憶。分頁太多是 §9 的問題之一。
- **地圖全幅模式**：地圖可以展開成蓋住中欄的大畫布，再按一次回到對話。

## 5. 畫面清單

每個畫面請標出：用到的元件、哪些是新元件、各種狀態。編號請沿用，之後實作會逐張對照。

### A 階段：核心與第一批功能（最優先，要完整）

**A1 對話清單**
- 列、搜尋結果、空狀態（第一次使用）、封存區、載入中。
- 列上的支線活動摘要：「3 條進行中・1 條等你」。

**A2 主線對話頁**
- 訊息：Markdown（標題、清單、表格、程式碼、數學式）、長訊息、正在串流、停止後的部分回覆、錯誤（可重試）。
- 每則訊息的動作：開支線、停車（B）、記進紀要、複製、釘選（C）。
- 選取文字的小工具列：「從這段開支線」「停車」「記進紀要」。
- **分岔點標示**：哪則訊息有支線、幾條、狀態，點了可以進入；不能干擾閱讀（§9 問題 3）。
- 結論卡訊息（見 A5）、搬移標記（「後面 6 則已移到支線『…』」）、章節分隔線。
- AI 建議開支線（A12）。

**A3 開支線**
- 入口：訊息動作、選取文字、輸入框旁（掛在最後一則）。
- 表單：目的（必填，最多 200 字，可由選取文字預填）、種類（順口問 / 查證 / 另一條路，附一句說明）、可換 provider 與 model、
  「也帶上分岔點之後主線的發展」選項、預覽背景會帶哪些內容與大約 token。
- 狀態與錯誤：深度超過 3 層要再確認、同一處開著的支線到上限（8）、整棵對話到上限（200）、分岔點已不在（被搬走）。

**A4 支線對話頁**
- 頂端固定的支線條：種類圖示、目的、從哪一則岔出來（可點回去並高亮）、選取的文字、背景（可展開看全文與 token）。
- 一眼看出「我在支線裡」與怎麼回主線（§9 問題 2、4）。
- 動作：結束並帶回、不帶回、升為主線、獨立成新對話（B）。
- 結束後唯讀：輸入框換成結果（「已帶回 → 結論卡」或「未帶回：原因」）。
- 順口問的樣子：較輕量，答完自動結束並顯示「7 天後清除」。

**A5 結論卡**（最重要的畫面之一）
- **起草中**：等待 AI 草稿（幾秒到一兩分鐘），可取消；失敗時給空白卡自己寫。
- **審閱與編輯**：欄位逐項可改、可刪、可加。
  - 問題、結論（必填）。
  - 依據：每條連到支線裡某則訊息，可點開看原文；最多 12 條。
  - 對主線的影響。
  - 還沒解決的（最多 10 條）。
  - **需要你決定的**（最多 8 條）：支線結論與主線後來的說法矛盾，兩邊各說什麼，並附主線那則訊息的連結。
  - 附上的原文片段（最多 3 段，例如指令、數字）。
  - 下半部：紀要的修改提案（要新增哪幾條、要取代哪一條，新舊並排），逐條勾選。
  - 要讓人感覺是在「審」AI 寫的草稿，而不是按下一步。
- **主線已經往前走**：草稿產生後主線又多了訊息，提示「主線多了 3 則，其中 1 則可能跟結論有關」，可選重新起草或照樣帶回。
- **在主線裡的樣子**：與一般訊息明顯不同的卡片；摺疊時顯示目的、結論、需要你決定的項目；可展開全部欄位；連到支線與分岔點。
  還沒送給 AI 之前有「下一輪才會告訴 AI」的小標記。

**A6 不帶回、升為主線**
- 不帶回：選填原因（B 階段會變成「死路」收尾）。
- 升為主線：清楚說明後果，最好有前後對照的小圖。主線分岔點之後的內容會變成一條灰色的「原本的主線」支線；
  掛在那段上的支線必須先結束；這條支線底下的子支線會往上提一層。

**A7 把最後 N 則搬成支線**
- 選擇從哪一則開始（必須是自己的訊息，最多 40 則），預覽會被搬走的訊息，填目的。
- 說明代價：主線下一輪要重新整理背景。
- 不能搬的情況：AI 正在回覆、範圍裡有結論卡。

**A8 支線大綱與地圖**
- 大綱：縮排的樹；每列：種類圖示、目的、狀態、收尾或一句結論、未讀 / 正在回覆 / 等你、「你在這裡」。
  未帶回的灰色；可收合；順口問預設隱藏，可切換顯示。
- 地圖：自動排版的樹（不手動拖節點），可縮放、平移、符合畫面；目前路徑高亮；點節點進入。
  匯出：Markdown 大綱、Mermaid mindmap、OPML。
- 窄寬度（420px 嵌入、手機）只給大綱。

**A9 紀要**
- 四區：已決定、已確認的事實、待確認、待辦。每條：內容、來源（哪條支線、哪則訊息，可點）、狀態。
- 被取代的條目劃掉並指向新條目，預設收合；可標記完成。
- 手動新增、修改、從訊息或選取文字「記進紀要」。
- 標示「這頁每一輪都會給 AI」，以及超過上限時哪些會被省略。

**A10 章節**
- 對話中的章節分隔線（標題、時間範圍）、側欄的章節清單（點了跳過去）、新增 / 刪除里程碑。
- 章節來源：話題切換（AI 摘要時判斷）、閒置超過 2 小時、手動里程碑。

**A11 送出前預覽與 token 計量**
- 頂端的小計量：這條線累計 token 與費用。不要讓人焦慮，§9 問題 6。
- 預覽抽屜：這一輪會送出的區塊（規則、背景、紀要、摘要、最近訊息、結論卡通知…）與各自的 token，可展開看內容。

**A12 AI 建議開支線**
- AI 回覆下方最多 3 個建議（目的 + 種類），按了才開，可忽略。

**A13 設定**
- 對話層級：provider、model、目標（C）。
- 外觀：淺色、深色、跟隨系統。
- 功能清單：哪些功能開著、各自的模式（手動 / 建議 / 自動），由宿主決定時顯示為唯讀。

**A14 全域狀態**
- 空狀態、載入中、連線中斷正在重連、唯讀身分（看得到但不能寫）、功能被關閉、AI 服務錯誤、達到上限。

### B 階段：收尾與減少發散（要完整）

**B1 收尾**
- 支線結束時的收尾：五種類型（結論 / 決定 / 答案 / 死路 / 待續）各有圖示與語意色，一句話，可展開詳述。
- 帶回時由結論卡自動產生；不帶回時填「死路」原因；AI 起草的收尾待確認。
- 收尾在大綱、地圖的樣子：樹的末端節點。

**B2 獨立成新對話**
- 兩種方式：把整條支線（含子支線與訊息）變成新對話；或從某一則訊息開一個全新的對話，只帶起始膠囊（路徑摘要、紀要快照、收尾）。
- 預覽膠囊內容與 token；選擇要不要複製紀要。
- 兩邊的連結標示：原對話裡的「已獨立 →」、新對話頂端的「來自…」。

**B3 停車場**
- 一鍵停車：訊息動作、選取文字、輸入框（例如輸入框旁的按鈕或快捷鍵）。
- 停車場清單：每顆種子可以展開成支線、記進紀要、丟掉；顯示來自哪則訊息。
- 數量要一直看得到（例如側欄標籤上的數字）。

**B4 樹平衡提示**
- 支線比主線還熱鬧時的提示：「這條支線已經比主線分岔後的內容多 2 倍，要升為主線，或獨立成新對話？」
- 三個選項：升為主線、獨立、維持（不再提醒）。出現在支線條與建議匣，不彈窗。

**B5 建議匣**
- 所有 AI 建議集中的地方：種類、對象、理由、接受 / 忽略。
- 側欄或頂端的入口與數量。

### C 階段：省 token 與結構（主要畫面）

**C1 魚眼脈絡的可視化**
- 在預覽與地圖上看出「這一輪 AI 看得到什麼」：完整、摘要、只有一句收尾、看不到，四種程度。
- 釘選訊息讓它一定會被送出。

**C2 群組與合併**
- 在地圖或大綱多選支線 → 建立群組：地圖上的外框，加上像 XMind「摘要」的括號與一段共同摘要。
- 合併支線的對話框：合併後的新支線、被合併的支線狀態、**互相矛盾的地方**列出來讓人決定。
- AI 建議的群組（從建議匣進來）。

**C3 關聯線**
- 在地圖上拉兩個節點之間的線並寫說明；AI 建議的關聯以虛線表示待確認。

**C4 目標與偏題提示**
- 對話頂端的一句目標（可編輯，可讓 AI 提案）。
- 偏題時在 AI 回覆下方輕輕提示「這段好像偏離目標，要開成岔題嗎？」

**C5 未完成清單**
- 一個「回顧」畫面：開著太久的支線、待確認的紀要、停車場的種子、未處理的建議。每一項可結束、暫存、繼續。

### D 階段：記憶與思考工具（主要畫面）

**D1 記憶**
- 記憶庫頁：事實、決定、偏好、教訓，各有出處（哪個對話、哪個收尾），被取代的保留歷史。
- 開新對話或支線時的「你之前得出過…」提示（可帶入、可忽略）。
- 這一輪帶入了哪些記憶（在預覽裡）。

**D2 論證節點類型**
- 訊息與地圖節點的類型標記：問題 / 想法 / 贊成 / 反對 / 決定（AI 標、可改）。
- 地圖可依類型篩選或上色。

**D3 發散與收斂**
- 發散：「給我 3 個方向」→ 產生 3 條兄弟支線。
- 收斂：選幾條支線 → 比較表（條件 × 選項，分數、理由、建議）→ 一鍵產生「決定」收尾。

**D4 折疊**
- 在對話中選一段訊息折疊成摘要節點（訊息還在，可展開），送給 AI 時只送摘要。
- 依章節建議可以折疊的範圍。

## 6. 功能開關對介面的影響

宿主可以只開核心。請示範兩種極端：

1. **只有核心**：對話、開支線、結論卡、帶回 / 不帶回 / 升為主線 / 搬移、大綱與地圖、送出前預覽。側欄只剩大綱與地圖。
2. **全部打開**：A–D 全部功能。

功能有四種模式，介面要能表達：
- **關閉**：完全不出現（不是灰掉）。
- **手動**：只有使用者按了才做，例如「起草結論卡」按鈕。
- **建議**：AI 提出、等你確認（建議匣、提示）。
- **自動**：AI 直接做，但要看得出是 AI 做的，而且可以復原或修改。

## 8. 假資料情境（請用這兩組內容）

**情境一：規劃家用 NAS 與備份策略**（A、B、C 階段的主要示範）
- 目標：「在 3 萬元內做出可以撐 5 年、不會因為單一故障而遺失資料的家用儲存與備份」。
- 主線約 40 則，章節：需求盤點 → 硬體選擇 → 檔案系統 → 備份策略。
- 支線：
  1. 查證「ZFS mirror 與 Btrfs RAID1 在單碟故障時的差異」：**已帶回**。
     - 結論卡：結論「兩者都能撐過單碟故障；ZFS 的 scrub 與自我修復較成熟」；依據 3 則；影響「檔案系統改用 ZFS mirror」；待解決「ECC 記憶體是否必要」。
     - 需要你決定：主線第 18 則說「預算內買 4 顆碟做 RAIDZ1」，支線結論認為「兩顆大碟做 mirror 比較好擴充」。
     - 子支線：順口問「scrub 多久跑一次？」（已回答，7 天後清除）。
  2. 另一條路「改用雲端備份（Backblaze B2），NAS 只做本地快取」：**進行中**，14 則，觸發樹平衡提示。
  3. 查證「4TB 與 8TB 硬碟的每 TB 成本與保固」：進行中，有 2 則未讀。
  4. 查證「二手企業碟可不可靠」：**未帶回**；收尾＝死路「通電時數普遍超過 4 萬小時、賣家保固只有 7 天，不划算」。
  5. 另一條路「用舊筆電當 NAS」：未帶回；收尾＝死路「只能接一顆碟、沒有 ECC」。
  6. 群組「硬碟選購」包含 3、4；共同摘要「新碟 8TB 每 TB 成本最低；二手企業碟風險高」。
- 停車場：「UPS 要不要買？」「異地備份多久同步一次？」「NAS 要不要開外網存取？」
- 紀要：
  - 已決定：檔案系統用 ZFS mirror（來源：支線 1 的結論卡）；預算上限 3 萬。
  - 事實：現有資料 2.1TB、每年成長約 400GB。
  - 待確認：ECC 記憶體是否必要。
  - 待辦：列出 3 款支援 ECC 的主機板。

**情境二：學習 Rust 的所有權與借用**（D 階段示範）
- 支線：
  - 順口問「為什麼 String 不能 Copy？」
  - 查證「生命週期標註什麼時候需要寫？」
  - 發散「用三種寫法實作單向鏈結串列」→ 三條另一條路：`Box`、`Rc<RefCell>`、arena。
  - 收斂比較表：條件為易讀性、效能、借用檢查的麻煩程度，建議用 arena。
- 記憶：「上個月的對話：你偏好先看能編譯的最小範例再看理論」（偏好）、「`&mut` 不能同時存在兩個」（事實，來源：Rust 入門對話）。
- 論證類型：問題「為什麼 borrow checker 拒絕這段？」→ 想法「改成 clone」→ 反對「效能差」→ 決定「改用索引」。

## 9. 請先回答的設計問題

1. **側欄的分頁太多**（大綱、地圖、紀要、章節、停車場、建議、記憶）：怎麼整合？哪些合併、哪些改成別的入口？
2. **進入支線**：整個對話區換成支線，還是主線留著、支線並排？桌機、嵌入側欄、手機可以不同。
3. **分岔點在主線訊息流裡怎麼標示**：看得到有支線、可以進入，但不干擾閱讀。
4. **結論卡與收尾的視覺關係**：結論卡是主線裡的訊息，收尾是樹上的節點，兩者內容相關但用途不同。
5. **AI 介入的強度分級**：訊息下方的提示、建議匣、地圖上的標記，什麼情況用哪一種？怎麼做到不打斷思考？
6. **token 與費用的呈現**：看得見、能預覽，但不讓人每打一句話都在算錢。
7. **地圖上的資訊層**：群組外框、關聯線、論證類型、魚眼程度同時存在時怎麼不亂（例如圖層開關）。
8. **只開核心時的樣子**：側欄只剩大綱與地圖時，版面怎麼保持完整。

## 10. 視覺方向（起點，可提案調整）

- 方向：**安靜的紙本思考筆記**。暖白紙張與墨色文字，一個代表「支線」的青綠色；資訊密度中等（比開發者工具寬鬆，比消費型聊天 app 緊湊）。
- 字體：介面用無襯線；AI 的長篇回答可以考慮用易讀的襯線字體（編輯感），程式碼用等寬。附件 `styles.css` 目前是 Inter + Source Serif 4 + JetBrains Mono，
  中文 fallback 為 Noto Sans TC / Noto Serif TC；可以換，但要說明理由，且必須能自架。
- 顏色：語意化。支線狀態（進行中 / 已帶回 / 未帶回 / 已升為主線）、收尾類型、論證類型、建議、警告、錯誤，各有固定的 token。
- 淺色是主要主題，深色要同樣用心；另外請示範一套「宿主主題」：放進深色開發者工具時的對應值。
- 動效：只用在說明狀態變化（開支線時的分岔、帶回時卡片回到主線、串流中）；關閉動效時要有替代。
- 避免：預設模板感的卡片格、全部一樣的圓角與陰影、只有一個裝飾色的灰白配色。
