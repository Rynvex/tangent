# 待後端確認的資料與行為

需求文件 §5 與附錄沒有寫到、但設計用到的資料或行為。「已定」= 10/15 已回覆；「待確認」= 還需要後端決定。

## 已定

| 項目 | 定案 |
|---|---|
| 魚眼程度（C1） | 後端組 prompt 時回傳每個區塊的程度（完整 / 摘要 / 只有收尾 / 看不到）與分數；前端只顯示 |
| 合併支線（C2） | 不新增狀態。資料是「未帶回」＋ `mergedIntoLineId`；前端看到它就顯示「已合併到…」並連到新支線 |
| 獨立成新對話（B2） | 新對話帶 `spunOffFrom`（來源對話、來源訊息、標題）；原支線或訊息帶 `spunOffTo` |
| AI 錯誤重試（A14） | 串流事件帶 `attempt`、`maxAttempts`、`nextRetryAt`；只有 429 與伺服器錯誤自動重試，其他直接顯示並提供手動重試 |
| 記憶提示（D1） | 只在開新對話與開支線時主動提示（可帶入、可忽略）；每輪自動帶入的記憶只出現在送出前預覽 |
| 結論卡驗證（A5） | 不開放略過審閱；後端驗證卡片內容 |

## 待確認

| # | 項目 | 設計上的需要 |
|---|---|---|
| 1 | 結論卡草稿的基準點 | 記錄「草稿產生時主線的最後一則」，才能顯示「主線多了 3 則，其中 1 則可能相關」 |
| 2 | 單輪 token 估算 | 前端可呼叫、不送出的估算 API；超過使用者門檻時才顯示金額 |
| 3 | 費用門檻設定 | 使用者設定（US$ 單輪門檻）存在哪裡、宿主能否預設 |
| 4 | 「等你」的定義 | 對話清單的「1 條等你」= 支線有未讀，或結論卡草稿待審 |
| 5 | 紀要「新」標記 | 需要 created-at 與使用者最後檢視時間 |
| 6 | 釘選訊息（C1） | 訊息物件加 pinned 欄位 |
| 7 | 合併時的矛盾選擇（C2） | 使用者對每個矛盾項的選擇（採用 A / 採用 B / 都保留→寫進待確認）需要欄位 |
| 8 | 搬移後改掛（A7） | 從被搬訊息岔出的支線要一併改 parent 到新支線 |
| 9 | 建議的持久化（B5） | 「已忽略、不再提醒」與樹平衡「維持」需要保存 |
| 10 | 比較表的決定（D3） | 產生「決定」收尾時，同時把其他兄弟支線設成「未帶回」＋死路收尾：需要一次性批次操作 |
| 11 | 記憶比對（D1） | 開新對話 / 開支線時，用什麼方式挑出相關記憶（目前原型各顯示 1–2 條） |
| 12 | 開太久的支線 | 「待處理」數量包含開太久的支線。原型用「進行中且 ≥ 12 則」暫代，建議改成「進行中且 3 天以上沒有活動」，需要最後活動時間 |
| 13 | 順口問保存 | 「記進紀要」寫入「已確認的事實」，來源指向順口問；順口問 7 天後清除時，紀要條目的來源連結要保留成文字 |
| 14 | 論證類型（D2） | 訊息與節點的類型欄位、來源（AI / 使用者修改） |
| 15 | 折疊（D4） | 折疊範圍（起訖訊息）、摘要、原 token 與摘要 token |
