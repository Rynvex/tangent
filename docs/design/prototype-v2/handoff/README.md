## 設計決定

### §9 八題

1. **側欄分頁**：三頁「結構、紀要、待處理」。
   - 結構 = 大綱 / 地圖 / 章節切換。
   - 紀要 = 這段對話的紀要；底部是「跨對話記憶」，用虛線框與標題和紀要分開。
   - 待處理 = 開太久的支線 + 停車場 + 建議匣，底部連到回顧（C5）。
   - 「待處理」標籤一直顯示數量（含 0）。
   - 關掉的功能，分頁直接消失；只開核心時沒有分頁列，只有標題「結構」。
2. **進入支線**：所有寬度都是整個對話區換成支線，v1 不做並排。支線條上的「預覽分岔點」浮層顯示主線那則與前後各一則，不切換畫面；「到那則訊息 →」才切回主線並高亮。
3. **分岔點標示**：訊息正文之後的一顆膠囊（支線數、狀態點、文字摘要），點開是內嵌清單。不用側邊線或行內標記。
4. **結論卡與收尾**：收尾是結論卡的標題列，結論卡是收尾的展開；兩者共用收尾類型的圖示與顏色。
5. **AI 介入分級**，由輕到重：
   - 標記：虛線、徽章，不需要回應。
   - 內嵌提示：回覆下方，每輪最多一則。
   - 建議匣：只有數字。

   不彈窗、不搶 focus。「虛線 = 還沒被你確認」。
6. **token 與費用**：預設只顯示 token；累計與單輪金額收在送出前預覽。單輪預估超過使用者設定的門檻（設定頁，US$0.02 / 0.05 / 0.10，預設 0.05）時，輸入框旁才以警告色顯示金額。
7. **地圖資訊層**：結構與狀態永遠顯示；群組、關聯、魚眼、論證類型是圖層開關。每種資訊用不同視覺通道：
   - 邊框色 = 狀態
   - 外框 = 群組
   - 虛線 = 關聯 / 待確認
   - 透明度 = 魚眼
   - 標籤 = 論證類型
8. **只開核心**：
   - 側欄只有「結構」。
   - 訊息動作只剩開支線、複製；輸入框只剩開支線、預覽。
   - 章節、建議、目標不渲染。
   - 容器一律用 gap 排列，少一個子元件仍對齊。

### 10/15 定案（覆蓋早期建議）

- **字體**：IBM Plex Sans / Mono；中文 IBM Plex Sans TC（`@ibm/plex-sans-tc`），缺字或缺字重退到 Noto Sans TC。AI 長篇回答用 Source Serif 4 / Noto Serif TC；介面一律無襯線。全部 OFL、自架。
- **宿主主題**：用宿主深色值，Geist / Geist Mono，全部無襯線（serif token 指向 sans）。
  - 新增 `--tg-primary-text`：`--tg-primary` 只當填色（按鈕底、選取線、圖示），文字與連結一律用 `--tg-primary-text`。
  - 狀態色與收尾類型色在 #090a0f 與 #12141d 上全部 ≥ 4.5:1，數值見 `tokens.css` 與色票頁。
- **順口問**：不提醒清除。支線條一直顯示「7 天後清除」，並提供「記進紀要」（寫入「已確認的事實」）與「停車」兩種保存方式。
- **結論卡審閱**：不開放略過。主按鈕「全部接受並帶回」一次點擊完成，會套用所有紀要提案；「需要你決定的」項目原樣留在卡上。次按鈕「依勾選帶回」。後端驗證卡片內容。
- **合併**：不新增狀態，見 `backend.md`。
- **記憶提示**：只在開新對話（輸入框上方）與開支線（表單內勾選）時主動出現；每輪自動帶入的記憶只在預覽的「記憶（跨對話）」區塊看得到。

### 其他決定

- **訊息樣式**：使用者訊息靠右、淺底；AI 回覆不加框、用襯線字；結論卡是唯一帶底色與邊框的訊息。
- **AI 草稿**：一律標「AI 草稿・待你確認」或虛線框。結論空白不能帶回。
- **功能模式**：
  - 關閉：不渲染，不是灰掉。
  - 手動：只有按鈕。
  - 建議：虛線提示或進建議匣。
  - 自動：直接做，但標出「AI 做的」並可改。

  宿主鎖定時設定頁唯讀。
- **寬度規則**：見 `components.md`。
