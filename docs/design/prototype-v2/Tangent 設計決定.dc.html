Tangent・設計決定 v2・2026-10-15

§9 設計問題的答案

每題：建議、理由、在原型裡的位置。檔案：原型（A–D）・C、D 畫面・色票・元件規格與快捷鍵・互動規格・交接文件。

定案（10/15 確認）

以下覆蓋本頁後面的「建議」。

  1. 字體：IBM Plex Sans / Mono；中文 IBM Plex Sans TC，缺字或缺字重時退到 Noto Sans TC。
  2. AI 長篇回答用 Source Serif 4 / Noto Serif TC，介面一律無襯線；宿主主題全部無襯線。
  3. 宿主主題改用宿主深色值，字體 Geist / Geist Mono。新增 --tg-primary-text：--tg-primary 只當填色。支線狀態色、收尾類型色在 #090a0f 上全部達 AA（見色票）。
  4. 側欄三頁「結構、紀要、待處理」。待處理標籤一直顯示數量（停車場＋建議＋開太久的支線）；關掉的功能分頁直接消失，只開核心時只剩「結構」；記憶放紀要底部，標明「跨對話」。
  5. v1 不做並排。支線條加「預覽分岔點」浮層：主線那則與前後各一則。
  6. 順口問不提醒清除；一直顯示「7 天後清除」，並提供「記進紀要」「停車」兩種保存方式。
  7. 不開放略過審閱；審閱畫面的「全部接受並帶回」只需一次點擊。後端驗證卡片內容。
  8. 預設只顯示 token，金額收在預覽裡；單輪預估超過使用者設定的門檻（設定頁）才主動顯示金額。
  9. 魚眼程度與分數由後端組 prompt 時回傳，前端只顯示。
  10. 不新增狀態：資料是「未帶回」＋ mergedIntoLineId，前端顯示成「已合併到…」並連到新支線。
  11. 新對話帶 spunOffFrom（來源對話、來源訊息、標題）；原支線或訊息帶 spunOffTo。
  12. 重試：串流事件帶 attempt、maxAttempts、nextRetryAt；只有 429 與伺服器錯誤自動重試。
  13. 記憶只在開新對話與開支線時主動提示；每一輪自動帶入的記憶只在送出前預覽裡看得到。
  14. 四項未做的互動留給實作；地圖拉關聯線與大綱鍵盤操作見互動規格。
  15. 原型加入情境二（學習 Rust），D1–D4 可在原型裡走完：對話清單點「學習 Rust 的所有權與借用」。
  16. 交接文件：handoff/（Markdown），不做 PDF。

1. 側欄分頁太多

建議：三個分頁——「結構」（大綱 / 地圖 / 章節，用切換鈕）、「紀要」（紀要；D 階段把記憶放在同一頁下半部）、「待處理」（停車場 + 建議匣 + 回顧入口，分頁上顯示總數）。

理由：依「看結構 / 看已定下的事 / 看還沒處理的事」分，而不是依資料類型分。七個分頁在 360px 裡放不下也記不住；三個分頁的數字只有「待處理」有，注意力只被一個地方拉。章節同時存在於訊息流的分隔線，側欄只是索引。

2. 進入支線

建議：所有寬度都是「整個對話區換成支線」，頂端固定支線條，主線的分岔點以連結與背景摘要呈現。

理由：並排會讓兩條線同時爭取閱讀，正好違反「不被岔題帶偏」；1440 寬並排後每欄都低於舒適閱讀寬度。需要對照主線時，支線條上的「從主線 #19 岔出」一鍵回到分岔點並高亮，Esc 返回。之後若要並排，建議只在 ≥1600 寬以「釘住主線」的唯讀窄欄提供。

3. 分岔點標示

建議：訊息正文結束後的一顆膠囊：「⑂ 2 條支線 ●● 1 進行中・1 未帶回」，點開是內嵌清單（種類、目的、狀態、收尾、未讀）。

理由：放在正文之後，讀完才看到，不切斷句子；不用左側邊線或行內標記，避免與選取、程式碼區塊衝突。狀態點用支線狀態色，色盲時仍有文字摘要。420 嵌入也能用同一個元件，不需要額外欄寬。

4. 結論卡與收尾的關係

建議：收尾是結論卡的「標題列」，結論卡是收尾的「展開」。兩者共用收尾類型的圖示與顏色（結論 = 旗標 + 靛色）。

理由：使用者在主線看到卡片的那一行粗體結論，就是大綱、地圖末端顯示的那一句；同一句話在兩處長得一樣，就不用解釋兩者的關係。結論卡用紫色卡片底（--tg-card）區分「系統訊息」，收尾只是一行文字。

5. AI 介入的強度分級

  1. 標記（最輕）：地圖、大綱上的虛線、待確認徽章。不需要回應。
  2. 內嵌提示：AI 回覆下方的虛線膠囊（建議開支線、偏題）。每輪最多一則，跟著那則回覆，捲走就消失；可以一鍵忽略。
  3. 建議匣：跨訊息、需要決定的事（樹平衡、群組、記進紀要）。只有數字，不彈出。

規則：建議永不搶 focus、不開對話框；同一件事只出現在一個層級（樹平衡例外：在支線條內嵌一次，同時進建議匣）。建議一律用 --tg-suggestion 紫色虛線框，「虛線 = 還沒被你確認」。

6. token 與費用

建議：三層——頂端灰色小膠囊只顯示這條線的累計 token（定案：不顯示金額）；輸入框的眼睛圖示在有輸入時才顯示「這一輪約 7.6k」；點任何一個才打開預覽抽屜。

理由：累計數字用來建立信任，不需要每一秒更新顏色；不用紅黃綠警示，只有接近上限時才變成警告色。預覽抽屜同時顯示「若送完整歷史約 38k」，讓人看到省下來的部分，而不是只看到花費。

7. 地圖的資訊層

建議：結構與狀態永遠顯示；群組、關聯、魚眼、論證類型是可疊加的圖層開關。顏色只表達一件事：節點邊框 = 路徑與狀態；論證類型以小標籤呈現，不改邊框色。

理由：同時用顏色表達三種分類就無法讀。外框（群組）、虛線（關聯、待確認）、透明度（魚眼「看不到」）、標籤（類型）分別用不同的視覺通道，可以同時開而不打架。

8. 只開核心時

建議：側欄的分頁列換成標題「結構」，下方直接是大綱 / 地圖切換；訊息動作只剩「開支線、複製」；輸入框只剩「開支線、預覽」；章節分隔線、建議膠囊、目標整列不渲染。

理由：被關閉的功能是「不存在」而不是灰掉，所以每個容器都要能在少一個子元件時仍然對齊（工具列用 gap 排列、側欄只有一個分頁時不顯示分頁列）。原型右側 Tweaks 的 features = core 可切換對照。

其他決定

  • 字體：介面 IBM Plex Sans、AI 長文 Source Serif 4、程式碼 IBM Plex Mono，中文 IBM Plex Sans TC（缺字退 Noto Sans TC）/ Noto Serif TC，全部 OFL。換掉 Inter，因為 Plex 的數字與中文搭配時的字重較接近，而且有同家族的等寬字。
  • 使用者訊息是靠右的淺底塊；AI 回覆不加框、用襯線字，像筆記本上的正文。結論卡是唯一帶底色與邊框的訊息。
  • 結論卡審閱的主按鈕寫「全部接受並帶回」，旁邊是「依勾選帶回」，沒有「下一步」；AI 起草的欄位標「AI 草稿・待你確認」；結論空白時無法送出。
  • 新 token（見 tangent-tokens.css）：warning-soft、success-soft、highlight、suggestion / suggestion-soft、leaf-*（5）、arg-*（5）、shadow-overlay、radius-sm / lg / full、text-* 字級、reading-width、leading-reading。
  • 宿主主題只覆寫 token：#5458e8 主色只當填色、文字用 --tg-primary-text #a5b4fc、Geist / Geist Mono、AI 回覆改用無襯線。

§5 沒提到、需要確認的資料或行為

  • 結論卡草稿要記錄「草稿產生時主線的最後一則」，才能算出「主線多了 3 則」與哪一則可能相關。
  • 「這一輪約 N token」需要前端可呼叫的估算 API（不送出）。
  • 對話清單「1 條等你」：需要定義「等你」＝支線有未讀，或結論卡草稿待審。
  • 紀要條目的「新」標記需要 created-at 與使用者最後檢視時間。
  • 釘選訊息（C1）需要在訊息物件上加欄位。
  • 已定：魚眼程度與分數由後端組 prompt 時回傳，前端只顯示。
  • 已定：合併：資料是「未帶回」＋ mergedIntoLineId，前端顯示「已合併到…」。矛盾項的使用者選擇仍需欄位（待確認）。
  • 搬移（A7）後，從被搬訊息岔出的支線要改掛到新支線；需要後端一併更新 parent。
  • 已定：獨立：新對話帶 spunOffFrom（來源對話、來源訊息、標題），原支線或訊息帶 spunOffTo。
  • 已定：重試：串流事件帶 attempt、maxAttempts、nextRetryAt；只有 429 與伺服器錯誤自動重試。
  • 建議（B5）需要「已忽略、不再提醒」的持久化，樹平衡的「維持」也一樣。
  • 比較表（D3）產生的「決定」收尾，同時要讓其他兄弟支線變成「未帶回」：需要一次性的批次操作。
  • 已定：記憶提示只在開新對話與開支線時；每輪自動帶入的只在預覽裡看得到。比對方式仍待後端定義。
