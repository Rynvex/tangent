# Tangent web demo：UI／功能體檢（2026-10）

日期：2026-10-24　範圍：`web/apps/demo` 與 `@tangent/react`（HEAD `e08467b`）　方式：唯讀，mock 模式實際操作與截圖

## 總評

核心流程已經完整可用，開支線、在支線裡談、審結論卡、帶回主線都走得通。結論卡、支線條、分岔點膠囊、紀要、待處理的視覺語言一致，深色與宿主主題也都有照顧到。
目前主要的問題是 P1–P3 功能一層層加上去之後，訊息周圍變得太擠：每則訊息都有論證類型下拉選單和 9 個動作，在觸控裝置上還會一直顯示。這違反設計簡報的「不打斷心流」與交接文件 §9-5「標記不需要回應」。
窄螢幕（420／375）大致可用，但有幾個具體的破版（結論卡審閱的底部列、觸控時頂列溢出、支線條佔掉約三分之一的畫面）。
功能面缺的是一般聊天工具的基本盤：改訊息、重新產生、對話改名、完整匯出、快捷鍵說明。另外有幾個做好的功能入口太深（回顧、記憶庫、支線改名）。

### 確認沒問題的部分（實際看過）

## 遇到的困難與限制

- 只用 mock：串流的分段、重連、伺服器的實際錯誤字串、支線的 token 用量，都以 mock 的行為為準。例如第 27 項推測是 mock 的資料問題。真 API 模式沒有跑（需要從 `git archive` 建置並起一個伺服器與資料庫，這次沒有必要）。
- mock 的論證類型每一輪都會標（F6 devlog 差異 4）；伺服器是每 3 則回覆標一次，所以第 1 項在真 API 下「待確認」會少一些。但每則都有空的 `類型…` 選單這點不受影響。
- `?state=loading` 在載入 600 ms 後截圖時，畫面已經和一般狀態相同，沒有看到骨架畫面（推測載入狀態只在很短的時間內出現）。
- 效能數字來自無頭的桌機 Chromium，靜態伺服器沒有 gzip；只能當相對參考，沒有做 CPU 降速的手機量測。
- 原型的 `?state=empty` 與 mobile 畫面在無頭瀏覽器裡有時候是一片空白，所以只用 `proto-desktop-*`、`proto-cd` 當比較基準。
