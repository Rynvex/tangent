# 專注模式 · 功能與規格（2026-10-24）

> 狀態：使用者 2026-10-24 決定範圍；設計稿第二版 2026-10-24 審過採用（收在 `docs/design/focus-mode/`）；**階段一 2026-10-25 完成**（`docs/devlog/FM1-focus-mode.md`）；**階段二（備忘、結束的支線改名）2026-10-25 完成**（`docs/devlog/B13-memo.md`）。和本規格不同的地方記在兩份 devlog。
> 對應：tangent `c9173aa` 之後。用語、token、元件名稱同 `UI_DESIGN_BRIEF.md` 與交接包 `1_CURRENT_UI.md`。

## 0. 一句話

想專心規劃一件事時，**對話和樹狀圖並排顯示、即時同步**；在樹上點節點就能整理它（改名、收尾、關聯、結構操作），並在節點上**寫筆記**：給 AI 看的「紀要」，或不給 AI 的「備忘」，之後可以把筆記帶進對話繼續談。

## 1. 使用者決定（2026-10-24）

| # | 問題 | 決定 |
|---|---|---|
| 1 | 筆記要哪幾種 | **兩種都要**：給 AI 的紀要（現有）＋不給 AI 的備忘（新功能，階段二） |
| 2 | 節點面板放哪裡 | **浮在地圖那一側**，不另開第三欄。看過設計稿後可能調整 |
| 3 | 聚焦子樹 | **要** |
| 4 | 結束的支線能不能改名 | **要**（階段二，後端要放寬） |

## 2. 不變的前提（設計時不能違反）

- **訊息與已送達的結論卡不能改。** 它們是歷史紀錄（DESIGN §5）。要修正結論，是取代一條紀要、寫一則備忘，或再開一條支線。面板上結論卡只能看、跳過去，不能編輯。
- **紀要整段對話共用一頁，每一輪都會給 AI**，有 token 預算與條數上限。在節點上寫紀要，只是把「出處」標成這個節點（`sourceLineId`），AI 看到的仍然是整頁。介面要讓人分得出這點。
- **備忘不會送給 AI**，送出前預覽也看不到，除非使用者按「帶進這一輪」把文字放進輸入框。
- **備忘不是「私人」的。** tangent 沒有帳號概念，看得到這段對話的人都看得到備忘（和紀要一樣）。用語用「不給 AI」，不要用「私人」「只有我看得到」。
- 不能拖曳節點改位置。結構改變只走現有的動作（升為主線、搬成支線、合併、不帶回），它們各有限制。
- 地圖仍是自動排版（DESIGN／原型的規則），只是放進分割畫面。

## 3. 階段

| 階段 | 內容 | 需要後端 |
|---|---|---|
| 一 | 版面與進出、同步、聚焦子樹、節點面板（現有可改的欄位與動作）、節點上的紀要、筆記數量標記 | 不用，全部用現有 API |
| 二 | 備忘（新功能 `memo`）、結束的支線改名 | 要（階段二實作） |

## 4. 版面

### 4.1 寬度規則

沿用 `demo/frame/layout.ts` 的斷點（1280／1100／1024／768）。

| 視窗寬 | 專注模式 |
|---|---|
| ≥ 1024，非嵌入 | **分割**：左對話、右地圖，中間是可拖的分隔線 |
| < 1024，或嵌入 | **分頁**：頂列下方一個「對話｜地圖」分段控制，一次顯示一邊（手機上地圖仍可用，但只有平移、縮放與面板，沒有拉關聯） |

【待設計確認】手機上要不要有地圖。現在窄寬完全沒有地圖（`1_CURRENT_UI.md` §3.1）；專注模式是第一次在窄寬給地圖，若設計判斷太擠，就讓 < 768 沒有專注模式，按鈕隱藏。

### 4.2 分割畫面（≥ 1024）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 頂列 52：路徑 › 目標膠囊 ……………… token  [專注 ●] ⋯ ⚙                         │
├───────────────────────────────────┬─┬─────────────────────────────────────────┤
│ 狀態列（選擇性）                   │ │ 地圖工具列：− 100% + ⌖ │ 跟隨 ● │ 聚焦子樹 ○ │ 圖層 │ 大綱/地圖 │
│ 支線條（只在支線裡）               │ │ ┌───────────────────────────────┐ ┌───────────────┐ │
│ ┌──── 訊息欄（≤ 46rem）────┐       │║│ │   主線 ── 支線 A ── A-1        │ │ 節點面板 320    │ │
│ │ AI・#1 ……                │       │║│ │      └─ 支線 B（你在這裡）     │ │ 標題／狀態       │ │
│ │              你・#2 [泡泡]│       │ │ │            └─ B-1             │ │ 目的、收尾      │ │
│ │ [結論卡]                  │       │ │ │                               │ │ 筆記（紀要｜備忘）│ │
│ └──────────────────────────┘       │ │ └───────────────────────────────┘ │ 關聯、群組      │ │
│ 輸入框                             │ │                                    │ 動作            │ │
└───────────────────────────────────┴─┴────────────────────────────────────┴───────────────┘
```

- 進入專注模式時，收起左邊的對話清單與右邊的側欄（離開時恢復進入前的開關狀態）。
- 分隔線：預設 50:50，視窗寬 < 1440 時預設 45:55（讓 1280 寬時地圖區 ≥ 640，面板仍浮在旁邊；設計稿回饋 2026-10-24）；對話最窄 420px、地圖最窄 360px；雙擊回到預設。鍵盤：分隔線可以 focus，←／→ 每次 5%，Home／End 到兩端的最小值（`role="separator"`、`aria-valuenow`）。
- 節點面板：寬 320，浮在地圖區的右側（`shadow-overlay`），**不會擠壓對話**。地圖區不到 640px 寬時，面板改成從地圖區底部升起（高度 60%）。沒選節點時不顯示。
- 送出前預覽（⌘⇧P）在專注模式一律用抽屜（mode `dialog`），不插成第三欄（避免體檢 #12 的問題）。
- 對話欄的內容與現在完全相同（訊息、選取工具列、輸入框、結論卡審閱）。專注模式不改對話欄。
- 頂列：路徑、目標膠囊、token 照舊。加「專注」切換鈕（亮起表示開著）。側欄切換鈕（⌘.）在專注模式隱藏。

### 4.3 分頁（< 1024、嵌入）

- 頂列下方：分段控制「對話｜地圖」，右邊顯示目前那一側的未讀或回覆中提示（例如地圖側「回覆中」小點）。
- 在地圖點節點進入某條線時，自動切回「對話」。
- 節點面板在地圖側從底部升起（sheet，模態，焦點陷阱）。

### 4.4 狀態列與錯誤

- 重連、AI 錯誤、唯讀、上限的狀態列放在**對話欄**上方（不跨到地圖）。
- 地圖載入失敗：地圖區顯示「無法載入地圖。」＋再試一次，對話照常可用。
- 讀不到支線清單時，不顯示節點面板。

## 5. 進入與離開

| 項目 | 規格 |
|---|---|
| 入口 | 頂列「專注」按鈕；命令面板「進入專注模式／離開專注模式」；快捷鍵（見 §10）；地圖全幅（`map-overlay`）工具列加「和對話並排」 |
| 離開 | 同一顆按鈕、同一個快捷鍵；Esc **不**離開專注模式（Esc 已經是「回上一層」與關閉浮層） |
| 記住 | 分割比例、跟隨、聚焦子樹、圖層開關、是否在專注模式：存在瀏覽器（`localStorage`，讀寫失敗時用預設）。換對話時保留「是否在專注模式」與比例，聚焦子樹重設 |
| 網址 | `?focus=1` 直接開（mock 截圖與分享用）；離開時移除 |
| 地圖全幅 | 專注模式裡沒有「全幅」鈕（已經是並排）；改成「收合對話」：把對話縮到最小寬，再按一次恢復 |
| 功能關閉時 | 專注模式是核心（大綱與地圖是核心），一定有。地圖不可用的宿主設定（嵌入且宿主關掉地圖）才隱藏入口 |

## 6. 同步

### 6.1 對話 → 地圖

- 「你在這裡」：目前所在的線在地圖上用現有的高亮（2px 邊框、目前路徑），並 `aria-current="location"`。
- **跟隨**（預設開）：換線、開新支線、從支線回來時，地圖平移讓「你在這裡」在畫面內；已經在畫面內就不動。動畫 200ms，減少動態時直接跳。
- 使用者手動平移或縮放後，跟隨自動暫停，工具列顯示「已暫停跟隨・回到這裡」；按了就跳回並恢復跟隨。也可以直接關掉跟隨。
- 即時狀態（不需重新整理）：新支線出現、回覆中、結束、帶回、不帶回、改名、群組、關聯。新出現的節點有一次 600ms 的淡入（減少動態時不做）。資料來源是現有的 `/events`（`branch.changed`、`notes.changed` 等），經 TanStack Query 失效重抓。
- 對話裡滑到某個分岔點（有支線掛在那則訊息上）時，地圖上那些子節點用 `--tg-highlight` 的實線光暈輕微標示（不用虛線：虛線在 Tangent 只代表「還沒被你確認」），離開就消失；只在跟隨開著時標示。要節流，不能每次捲動都重算。

### 6.2 地圖 → 對話

- **單擊節點＝選取**：打開節點面板，對話**不動**。這樣可以邊看對話邊整理別的節點。
- **進入那條線**：雙擊節點、選取後按 Enter，或面板上的「到這條」。對話切到那條線；地圖**不關**、跟隨照舊。
- 現在全幅地圖的「選節點就進入並關閉」只在全幅裡保留；專注模式用上面的規則。
- 多選（群組）、拉關聯（R）、縮放、`0` 符合畫面：照現有地圖的規則。

### 6.3 聚焦子樹

- 工具列「聚焦子樹」開關。打開時，以**選取的節點**（沒選就用「你在這裡」）為根，只有它的子樹和它到主線的路徑保持全亮，其他節點淡到 30%、連線淡到 20%，但仍可點。
- 地圖自動「符合畫面」到那棵子樹。
- 工具列顯示「聚焦：{title}」＋「×」取消。
- 進入子樹外的線時：聚焦不自動移動，工具列提示「你在聚焦範圍外」＋「改聚焦這裡」。
- 和魚眼圖層同時開時：魚眼只套外框透明度（現有規則），聚焦的淡化套整個節點；兩者疊加時以較淡者為準。【待設計確認】視覺上分不分得出。
- 對話這側不受影響（聚焦只改地圖的顯示，不改 AI 看到的東西）。介面上寫清楚：「只影響地圖顯示，不影響 AI。」

## 7. 節點面板

### 7.1 結構

由上到下。各區塊沒有內容、或功能關閉時整塊不出現（不留空標題，避免體檢 #11 的問題）。

| 區塊 | 內容 | 可編輯 | 來源 |
|---|---|---|---|
| 標頭 | 種類圖示、標題（＝支線目的）、狀態文字、「你在這裡」標記、「到這條」、關閉 | 標題可點兩下或按 F2 修改（見 7.2） | `BranchView` |
| 位置 | 「從主線 #{n} 岔出」或「從 {parent} 的 #{n} 岔出」；分岔處的論證類型（`ibis`） | 論證類型可改 | 現有 |
| 收尾 | 一句話結論（`leaf`），只在支線結束後 | 可改、可清除 | `PUT/DELETE /lines/{id}/leaf` |
| 結論 | 帶回的結論卡摘要（前 3 行）＋「到結論卡」 | **不可改**；旁邊寫「結論卡是歷史紀錄，要修正請寫紀要或備忘」 | 現有 |
| 筆記 | 見 §8 | 是 | 紀要現有、備忘階段二 |
| 關聯 | 和這個節點有關的關聯（兩端都是連結）、說明；「新增關聯」 | 改說明、刪除（可復原）、新增 | 現有 |
| 群組 | 所在的群組名稱與共同摘要的第一行；「到群組」 | 改名 | 現有 |
| 動作 | 依狀態列出：結束並帶回（進行中）、不帶回、升為主線、獨立成新對話、開支線（從這條的最後一則） | 打開現有的對話框 | 現有 |
| 統計 | 「{count} 則訊息・{children} 條支線」，最後更新時間 | 否 | 現有 |

主線節點：標頭寫「主線」，沒有位置、收尾、結論；標題就是對話標題（`PATCH /lines/{id}`）。
順口問節點：只有標頭、位置、筆記與「{days} 天後清除」；動作只有「記進紀要」「停車」（現有規則）。

### 7.2 改標題（目的）

- 進行中的支線：階段一就能改（現有 `PATCH /lines/{id}/branch`，≤ 200 字）。
- 已結束（帶回、不帶回、升為主線、已合併）：**階段二**。階段一時這些節點的標題不可編輯，滑過去提示「結束的支線要等下一版才能改名」。【待確認】要不要階段一就先隱藏提示。
- 階段二改名時，提示一行：「改名後，主線之後的回合裡，這張結論卡的來源會用新名字。」
- 主線：改對話標題。
- 已封存的對話：都不能改。
- 編輯：Enter 存、Esc 放棄、空白不能存（「目的是必填。」）。存檔中按鈕停用。失敗時：節點與地圖上的標題維持原本的，輸入框**保留使用者打的字**並維持編輯狀態，下方顯示錯誤（`role="alert"`），可以直接再按儲存。

### 7.3 唯讀與權限

- 唯讀（`readonly`）：面板照常顯示，所有編輯控制換成純文字；面板頂端一行「你只有檢視權限。」
- 回覆中的線：標題、動作照現有規則（例如回覆中不能帶回）；筆記可以寫。

## 8. 筆記

### 8.1 兩種筆記

面板的筆記區頂端是分段控制：**紀要（給 AI）｜備忘（不給 AI）**，每一側帶數字。

| | 紀要 | 備忘 |
|---|---|---|
| 給不給 AI | 每一輪都給（整頁，有預算） | 不給 |
| 範圍 | 整段對話共用；掛在節點只是標出處 | 屬於這個節點 |
| 分區 | 已決定、已確認的事實、待確認、待辦 | 沒有分區，依時間排 |
| 修改 | 點一下改、完成、取代（舊的劃掉保留） | 點一下改、刪除（5 秒可復原） |
| 上限 | 現有的條數與 token 上限 | 每段對話 500 條、每則 4,000 字（階段二定案） |
| 出處被清除後 | 照現有規則，用 `sourceLabel` 顯示 | 同樣保留，顯示「出處已清除：{label}」 |
| 功能開關 | `notes` | `memo`（階段二新功能） |

- 只開其中一種時，不顯示分段控制，直接顯示那一種的標題。兩種都關時，沒有筆記區。
- 紀要側頂端照紀要分頁的寫法：「這頁每一輪都會給 AI・約 {tokens} / {budget} token」，並加一行小字「掛在這個節點只是標出處，AI 看到的是整頁紀要。」
- 紀要側只列 `sourceLineId` 等於這個節點的條目；下方「看全部紀要」打開側欄的紀要分頁（專注模式裡用覆蓋式側欄）。
- 備忘側頂端：「不會給 AI。看得到這段對話的人都看得到。」

### 8.2 新增

- 紀要：文字框＋分區選擇（預設「待確認」），送出時帶 `sourceLineId`＝節點。滿了照現有規則（`aria-disabled`、說明要先完成或取代）。
- 備忘：文字框，Enter 存、⇧Enter 換行、Esc 取消（同紀要的行內編輯）。
- 從對話來的捷徑：選取文字的工具列在專注模式多一個「記成備忘」（階段二，`memo` 開時），存到**目前所在的線**的節點。⌘⇧N（記進紀要）照舊（出處是那則訊息，`demo/frame/note-actions.ts` 傳 `sourceMessageId`）。

### 8.3 用筆記繼續討論

每則筆記（紀要或備忘）的選單：

| 動作 | 行為 |
|---|---|
| 帶進這一輪 | 把文字加到**目前所在的線**的輸入框開頭，格式「關於「{節點標題}」的筆記：{文字}」，焦點移到輸入框。不自動送出。若輸入框已有內容，加在最前面並空一行。送出前預覽會出現在「你的訊息」裡 |
| 從這裡繼續談 | 打開現有的開支線對話框：掛在**這個節點那條線的最後一則訊息**，目的預填筆記的第一行（≤ 200 字截斷），選取文字欄放整則筆記。其他規則照開支線對話框（上限、深度、封存）。若那條線已結束，掛在它的父線的分岔訊息上，並在對話框說明 |
| 轉成紀要（只有備忘） | 開一個小表單選分區，建立紀要（出處＝節點）；成功後備忘標「已轉成紀要」並保留，可以手動刪 |
| 到來源（只有紀要，有來源訊息時） | 進入那條線並捲到那則訊息 |

### 8.4 地圖上的標記

- 節點右下角：筆記數量小標記，圖示 `NotebookPen`＋數字（紀要＋備忘合計）。縮放 < 75% 時只顯示圓點。0 不顯示。
- `aria-label`：「{n} 則紀要、{m} 則備忘」。
- 圖層開關多一個「筆記」（預設開），可以關掉標記。

## 9. 狀態清單（設計稿每一項都要有畫面）

1. 剛進入：跟隨開、沒選節點、面板不顯示。
2. 選了進行中的支線：面板完整；標題可編輯。
3. 選了已結束的支線：收尾、結論、改名（階段二）。
4. 選了主線；選了順口問。
5. 筆記：紀要側有 3 條、備忘側空（空：「還沒有備忘。寫下不給 AI 的想法；看得到這段對話的人都看得到。」）；紀要滿了；備忘編輯中；刪除後的復原。
6. 「帶進這一輪」之後輸入框的樣子。
7. 跟隨暫停（使用者平移過）。
8. 聚焦子樹開：子樹全亮，其他淡化；「你在聚焦範圍外」。
9. 回覆中的節點、新出現的節點。
10. 唯讀。
11. 只開核心（`?features=core`）：沒有收尾、關聯、群組、論證類型；筆記區只剩紀要或沒有（`notes` 關時）。
12. 地圖載入失敗；面板存檔失敗。
13. 寬度：1440、1280、1024 分割；420、375 分頁。淺色、深色、宿主主題。
14. 分隔線拖到兩端（對話最窄、地圖最窄）；地圖區 < 640 時面板改到底部。

## 10. 鍵盤與無障礙

| 按鍵 | 動作 | 備註 |
|---|---|---|
| ⌘⇧F | 進入／離開專注模式 | 加進 `DEFAULT_COMMANDS`，宿主可改鍵。【待確認】各瀏覽器有沒有搶走（Firefox 已知搶 ⌘⇧P／⌘⇧M／⌘⇧S）；有衝突就改用 ⌘\ |
| F6／⇧F6 | 在「對話」「地圖」「節點面板」三區之間移動焦點 | 標準的區塊切換鍵；Tab 仍是一般順序 |
| Enter（地圖） | 選取的節點：進入那條線 | 單擊／Space 只選取 |
| F2（地圖、面板） | 改選取節點的標題 | 同大綱 |
| N（地圖，沒有修飾鍵） | 在選取的節點新增備忘（`memo` 關時是紀要） | 文字框裡不觸發 |
| Esc | 先關最上層的浮層（面板的編輯、面板本身），再輪到「回上一層」 | 不離開專注模式 |

- 三個區塊都是 `region` 並有名稱：「對話」「地圖」「節點面板」。
- 面板打開時焦點**留在地圖**（不搶焦點），面板用 `aria-live="polite"` 讀出節點標題；按 F6 才進面板。
- 自動跟隨不移動焦點。
- 減少動態：跟隨、淡入、聚焦的過場都直接切換。
- 筆記標記、聚焦的淡化不能只靠顏色：淡化的節點 `aria-description`「在聚焦範圍外」。

## 11. 實作注意（給寫程式的 agent）

- 主程式 JS 現在 176.91 kB gzip，上限 180 kB。專注模式整塊（分割畫面、節點面板、筆記區）**延遲載入**，地圖本來就是延遲載入。
- 地圖元件 `BranchMap`（`react/structure/branch-map.tsx`）現在 `onEnter` 一個回呼兼做選取與進入；要拆成 `onSelect`／`onEnter`，並加 `selectedLineId`、`focusRootId`、`follow`、`noteCounts`。注意現有的 `selected` 是群組的**多選**（`map-node.tsx:50`），和專注模式的「選取一個節點看面板」是兩回事，名稱與樣式都要分開。全幅地圖與側欄地圖的行為保持不變（它們傳同一個回呼給兩者）。
- 節點面板做成 `@tangent/react` 的元件（例如 `NodePanel`），demo 只負責版面；宿主之後可以重用。
- 紀要依節點過濾：用現有 `useNotes(rootLineId)` 在前端以 `sourceLineId` 過濾，不要新增 API。
- 建立紀要帶 `sourceLineId`：現有 `POST /lines/{id}/notes` 已支援（`httpapi/notes.go:35`）。
- 所有文字放 i18n（zh-TW、en），沿用現有用語（紀要、支線、收尾、結論卡…）。
- mock（`VITE_TANGENT_API=mock`）要能展示每個狀態；階段二前，mock 的 `memo` 能力預設關。
- 測試：分割比例的鍵盤操作、跟隨暫停與恢復、聚焦子樹的範圍計算（純函式）、F6 焦點循環、面板唯讀、帶進這一輪的文字格式、減少動態。Playwright 在 1440／1024／375 截圖。

## 12. 驗收（階段一）

1. 1440 寬按 ⌘⇧F：對話與地圖並排，對話清單與側欄收起；再按一次恢復原狀。
2. 在對話裡開支線：地圖即時出現新節點，「你在這裡」移過去，地圖跟著平移。
3. 單擊另一個節點：面板打開，對話不動；按「到這條」：對話切過去，地圖仍在。
4. 開聚焦子樹：只有那棵子樹全亮；離開範圍時有提示。
5. 在節點上寫一條紀要：側欄紀要分頁看得到，出處是那個節點；送出前預覽的紀要區塊有它。
6. 「帶進這一輪」：輸入框出現正確格式的文字，沒有自動送出。
7. 375 寬：「對話｜地圖」分頁可用，面板是底部抽屜。
8. 唯讀、只開核心、減少動態各走一遍。
9. Web 全部驗證通過，主程式 JS ≤ 180 kB gzip。

階段二另加：備忘的新增／修改／刪除／復原／轉成紀要，備忘**不出現在送出前預覽與 prompt**，結束的支線可以改名。
