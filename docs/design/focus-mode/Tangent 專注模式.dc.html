專注模式：對話與地圖並排，在地圖上整理節點、寫筆記

§9 的 14 個狀態每一項都有畫面，淺色、深色各一；420 寬另加宿主主題。分割畫面有 1440、1280、1024 三種寬度，分頁畫面有 420、375 兩種。沿用 --tg-* token 與現有元件，不改風格。地圖延用樹狀圖原型的自動排版（由左到右的邏輯樹），只是放進分割畫面。

階段二只在階段二出現（備忘、結束的支線改名、記成備忘）。這是設計標示，不是介面的一部分 你在這裡對話目前所在的線 地圖上選取的節點（面板正在看它）
畫面主題
每個畫面都有淺色和深色；選「並排」會同時顯示兩種。下方一次顯示一節，選「全部」會一次載入所有畫面，比較慢。
§9-1

S1 剛進入：跟隨開、沒選節點、面板不顯示

S1・1440・{{ th.label }}・視窗 ≥ 1440 預設 50:50；< 1440 預設 45:55

改了什麼

  • 對話清單和側欄收起，頂列的側欄切換鈕不顯示；「專注」鈕亮起（--tg-primary-soft），再按一次就離開。
  • 左邊是對話，內容和現在完全一樣；右邊是地圖，中間是分隔線（50:50）。
  • 地圖工具列由左到右：縮放與符合畫面、跟隨（預設開）、聚焦子樹、圖層、大綱／地圖。
  • 「你在這裡」改成節點上方的實心小標籤，加上到主線的路徑用 2.5px 主色連線。

為什麼

  • 「你在這裡」和「選取」在專注模式會同時出現在不同節點上。現在的 2px 邊框只能表達一種，所以「你在這裡」改用標籤加路徑，選取用底色加外光暈，一眼就分得出兩者。
  • 跟隨的開關要看得到，因為它會自動移動地圖；做成可以切換的按鈕，比藏在選單裡好懂。
§9-2

S2 選了進行中的支線：面板完整，標題可以改

S2・1440・{{ th.label }}・滑過標題

改了什麼

  • 單擊節點就是選取：面板浮在地圖右側（寬 320、shadow-overlay），對話不動、也不被擠。
  • 面板的區塊依序是：標頭、位置、筆記、關聯、動作、統計。沒有內容的區塊整塊不出現，這條沒有收尾和結論卡，所以不顯示那兩區。
  • 標頭右上角是「到這條 ↵」和關閉。標題滑過時出現鉛筆和底色，點兩下或按 F2 就能改。
  • 地圖會平移到讓選取的節點和它的上一層都在面板左邊看得到。

為什麼

  • 筆記放在動作前面，因為它是這次新增的主要用途。結構動作（帶回、升為主線）不常用，但後果大，所以放在下方。
  • 「升為主線」在這條是停用的，並附上原因（只有直接開在主線上的支線能升），而不是直接隱藏，這樣使用者才知道為什麼不能用。
§9-3

S3 已結束的支線：收尾、結論、改名（階段二）

S3a・1440・{{ th.label }}・階段二：改名中
S3b・1280・{{ th.label }}・只有階段一

改了什麼

  • 多了收尾（可以改）和結論卡摘要（前 3 行）。結論卡用 --tg-card 底色加鎖頭，旁邊寫「結論卡是歷史紀錄，要修正請寫紀要或備忘」，只能「到結論卡」，沒有編輯控制項。
  • 階段二：標題可以改，編輯時多一行說明「改名後，主線之後的回合裡，這張結論卡的來源會用新名字。」

為什麼

  • 階段一不顯示「下一版才能改名」的提示，理由見下面〈待設計確認〉第 4 點。
§9-4

S4 選了主線；選了順口問

S4a・1280・{{ th.label }}・主線
S4b・1280・{{ th.label }}・順口問
  • 主線：標頭只寫「主線」，沒有狀態、位置、收尾、結論；標題就是對話標題（可以改）；動作只有「開支線…」。
  • 順口問：只有標頭、位置、「3 天後清除」、筆記，動作是「記進紀要」「停車」。標題不能改：順口問 7 天後就清除，不值得改名。順口問有目的，紀要的出處寫「順口問・{目的}」。
  • 選了順口問時，就算大綱沒開「顯示順口問」，地圖也會把它畫出來，否則面板會對應到一個看不到的節點。

S5 筆記：紀要 3 條、備忘空、紀要滿了、備忘編輯中、刪除後復原、筆記的選單

S5a・1440・{{ th.label }}・紀要側 3 條
S5b–S5f・節點面板・{{ th.label }}

S5f 紀要的選單
S5g 備忘的選單階段二

改了什麼

  • 分段控制的兩邊都寫出「給 AI／不給 AI」，並帶數字。紀要側用 Eye 圖示，備忘側用 EyeOff 圖示。
  • 紀要側頂端兩行：「這頁每一輪都會給 AI・約 1.1k / 2k token」和「掛在這個節點只是標出處，AI 看到的是整頁紀要。」底部是「看全部紀要（18）→」。
  • 紀要條目左邊有「完成」勾選框（同 1_CURRENT_UI §4.11.2）。勾選後文字劃掉、底色變淡，並寫上完成時間；選單裡也有「標成完成」。備忘沒有完成。
  • 紀要滿了：「新增」按鈕 45% 不透明、aria-disabled，下方寫原因與解法。
  • 刪除備忘後，條目劃掉並淡化，下方出現深色提示列「已刪除一則備忘。復原」並倒數。
  • 選單裡，「帶進這一輪」「從這裡繼續談」放最上面；紀要有「到來源」「取代…」，備忘有「轉成紀要…」「刪除」。

為什麼

  • 「給不給 AI」是兩種筆記最大的差別，所以直接寫在分段控制的名稱裡，不必另外解釋。
  • 文案修正：規格的備忘空狀態寫「寫下只給自己看的想法」，這和 §2「備忘不是私人的」衝突。我改成「還沒有備忘。寫下不給 AI 的想法；看得到這段對話的人都看得到。」
  • 復原用面板內的提示列，不用全域 toast，因為焦點和視線都在面板上。

S15 地圖的兩種呈現方式：分層樹（預設）＋收尾分組

S15a・1440・{{ th.label }}・收尾分組，選了已帶回的支線
S15b・375・{{ th.label }}・收尾分組

改了什麼

  • 地圖工具列多一顆「呈現方式」下拉選單，只有兩個選項：分層樹（預設）、收尾分組。地圖區小於 640 時只顯示圖示。
  • 收尾分組依收尾分欄：結論、決定、答案、待續、死路、還沒有收尾；沒有項目的欄不顯示。這個版面沒有連線，每張卡片的第二行改寫「來自哪條線」。
  • 選取、面板、筆記標記、聚焦子樹、唯讀，在兩種方式下都一樣。聚焦子樹在收尾分組裡同樣是把範圍外淡到 30%。
  • 這個樹狀圖取代現有的「地圖全幅」。專注模式裡的「收合對話」就是全幅。入口沿用專注模式（頂列、命令面板、⌘⇧F），另外在待處理的「回顧」加上「在專注模式打開」。

為什麼第二種選收尾分組

  • 專注模式是為了回顧與整理。分層樹回答「這件事怎麼拆開的」，收尾分組回答「我已經得出了什麼、哪些是死路、哪些還沒收尾」，兩者互補。心智圖、組織圖和分層樹是同一棵樹換方向，資訊重複。
  • 收尾分組直接把剪枝的對象排在一起：「還沒有收尾」和「待續」兩欄就是要處理的清單，「死路」一欄可以檢查有沒有該圈成群組的。
  • 它不需要新資料，只用現有的 leaf；排版也最簡單（固定欄寬、依序往下排），延遲載入的大小影響最小。
  • 時間軸要加日期才有意義，而且排版和分層樹衝突的地方最多，先留在原型。
小地圖：這次不做，也不出建議稿。目前範例最多 28 條支線，「符合畫面」加上自動收起第二層以下、「+N」、聚焦子樹，已經能在一個畫面內找到位置。之後如果真實資料常超過 60 條支線，或使用者回報在大樹裡迷路，再評估。
