## 和工單不同的地方

1. **型別名稱**：工單的 `LineOrganization` 在 Go 的 `domain` 已經是「一條主線正規化後的資料夾與標籤」，所以後端叫 `domain.TenantOrganization`、`Engine.TenantOrganization`、`store.TenantOrganization`。JSON 形狀照工單。前端照工單叫 `LineOrganization` / `getLineOrganization()`。
2. **檔案位置**：查詢在 `store/queries/lines.sql`（不是 `postgres/queries`）；契約樣本加在既有的 `b18` 流程（沒有 `b18FolderTagFilter`）。新的 domain 測試放在新檔 `domain/decompose_test.go`（既有的 decompose 測試在 `domain/b18_test.go`）。
3. **排序用 `COLLATE "C"`**：工單寫 `ORDER BY folder ASC`；資料庫預設排序規則會隨安裝不同，改成 code point 順序，mock 也照這個比較。畫面上的資料夾仍用 `localeCompare` 排。
4. **租戶標籤進 decompose**：前端 `filterSuggestedTags` 有「其他對話已在用的標籤原樣保留」，為了讓伺服器結果和前端一樣，`DecomposeInput` 多了 `TenantTags`，store 多讀一次 `ListTenantTags`。工單沒寫。
5. **清理在取前 5 個之前**：工單沒指定；先清理再截，否則碎片會占掉名額。前端再清一次結果不變。
6. **主題詞內的縫合只接重疊的**：工單寫「重疊或相接」，前端（協調者指定為參考）只接重疊的，照前端。主題詞最長 8 字（前端的 `MAX_SEGMENT_RUNES`），沒有另外切成 6 字；6 字上限只用在清單中的串接（工單的 `總長 <= 6`），前端也加了同樣的上限。
7. **前端的 `filterSuggestedTags` 也改了**：`joinInWord` 比對任何長度的詞，否則伺服器接好的 `微分幾何` 會被前端丟掉（舊的只比對兩字）。
8. **mock 的章節切點**：工單寫「其餘切點移往 `chaptersByLine[id]`」；mock 和伺服器一樣是每個對話（主線）一份，切點跟著訊息走，支線的章節清單本來就會列出訊息在支線上的切點，所以只把「每一種最新的」改掛到標記上。工單寫「範圍內最後一則的切點」，Go 是**每一種**（`kind`）各取最新的一個，照 Go。
9. **mock 的摺疊事件內容**：搬走的摺疊在事件裡帶新的 seq。Go 原本帶舊的（見上「順手修的伺服器小錯」），兩邊都改成存的值。
10. **worker 門檻與 DOM**：工單沒指定門檻，用 1 MiB（小檔直接解析比開 worker 快，既有測試與 e2e 的小 fixture 照舊在主執行緒）。需要 DOM 的檔案（HTML、帶 HTML 的 Gemini JSON）回主執行緒解析，所以這兩種大檔仍可能卡一下。
11. **`shell.tsx` 643 行**：工單目標約 620；F13 的狀態與接線都移出去了，剩下超過的部分不是 F13 的。

## 審查與修正

兩個唯讀審查 agent（Go、TypeScript），沒有 CRITICAL。修掉的：
- TS HIGH：worker 從 `import-parse.ts` 拿常數與型別，而那個檔案自己 `new Worker(...)` 這個 worker（建出來的 chunk 剛好被 tree-shake 掉，但依賴是循環的）→ 拆出 `import-worker-protocol.ts`。
- TS MEDIUM：對話框關掉時若 `file.text()` 還沒回來，之後會改走主執行緒解析並 `setFile` 到已卸載的元件 → 卸載時遞增讀檔版本號，沒有 parser 就不解析。
- TS MEDIUM：`postMessage` 同步丟錯（例如 DataCloneError）時 worker 沒結束；回覆讀不出來（`messageerror`）時一直停在「解析中」→ 兩者都改成在頁面解析並結束 worker，有測試。`parse` 一律回 promise。
- Go／TS MEDIUM：「再清一次不變」不成立：`["微分","何在","分幾"]` 第一次得到 `["微分","分幾"]`（碎片擋住串接），第二次變 `["微分幾"]` → 兩邊都先把會被丟掉的拿出清單再串接，兩邊都有測試。
- Go MEDIUM：Go 的 `titleTopicWords` 截了標題、前端沒有 → 拿掉截斷（標題本來就有長度上限）。
- Go LOW：`ListTenantTags` 改 `COUNT(DISTINCT l.id)`（同一條線重複的標籤不重算）；`DecomposeBase` 註明只算未封存主線的標籤。
- TS LOW：建立、PATCH、封存／解除封存一條線的 mutation 也 invalidate 組織統計（之前只靠事件）。

沒有改的：Go 對已正規化的詞再 `NormalizeTag` 一次（`"# #a"` 這種輸入 `orderedTerms` 產生不出來，和前端處理伺服器清單的方式一致）；worker 的 `self` 型別用一個最小介面轉型（demo 的 tsconfig 沒有 webworker lib）。

## 留著的

- 需要 DOM 的大檔（HTML 匯出、帶 HTML 回答的 Gemini JSON）仍在主執行緒解析。要搬進 worker 得換一個不靠 DOM 的 HTML 解析器。
- 前端 `filterSuggestedTags` 的一個怪處照搬到伺服器：主題詞裡有一個雙字詞剛好是租戶已用的標籤時，它原樣保留，其餘的雙字詞照樣縫合，可能得到 `微分幾`（例如租戶已有 `幾何`）。改的話兩邊要一起改。
- `GET /lines/organization` 每次都彙總整個租戶的主線，沒有快取；一般租戶的大小沒問題，很大的租戶可能要索引或快取。
