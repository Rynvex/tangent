## 做了什麼

### client
- `branch-map-focus.ts`：`focusScope`（聚焦時保持全亮的節點：子樹＋往主線的路徑）、`subtreeKeys`（「符合畫面」只算子樹本身，不算往上的路徑，否則地圖會縮到 50%）、`noteCountsByNode`（依 `sourceLineId` 數每個節點的紀要，不含被取代的）。

### react
| 項目 | 內容 |
|---|---|
| `BranchMap` | 新的選填 props：`onSelect`（單擊＝選取；雙擊或 Enter＝`onEnter`）、`selectedLineId`、`focusLineId`、`follow`＋`onManualMove`、`noteCounts`、`coveredRight`／`coveredBottomShare`（面板蓋住的地方，選取的節點會移到看得到的位置）、`toolbar`、`extraLayers`、`overlay`、`highlighted`。**沒傳 `onSelect` 時行為不變**（側欄地圖、全幅地圖照舊）；既有的 `selected` 多選完全沒動，專注模式的選取用 `aria-expanded` 與 `ring`，多選用 `aria-pressed` 與勾 |
| `useMapFocus`（新） | 跟隨（只在不在畫面內時平移，減少動態時直接跳）、選取的節點避開面板、聚焦時符合畫面（最多 100%）、新節點淡入 600 ms |
| `MapNodeView` | 「你在這裡」標籤（淡化時仍全亮，S8b）、聚焦範圍外 30% 與 `aria-description`、紀要數量標記（< 75% 只剩圓點，名稱裡念「{n} 則紀要」）、分岔點的實線光暈 |
| `NodePanel`（新，`focus/`） | 標頭、改標題（`NodeTitle`）、位置、收尾（沿用 `BranchLeaf`）、結論卡（唯讀＋到結論卡）、紀要（`NodeNotes`）、關聯、群組、動作、統計。動作只回報給宿主，由宿主開既有的對話框 |
| `NodeTitle` | 進行中的支線與主線可改；Enter 存、Esc 放棄、空白不能存；**失敗時輸入框保留打的字**，按鈕變「再儲存一次」，錯誤 `role="alert"` |
| `NodeNotes` | 只列 `sourceLineId` 是這個節點的紀要；頂端寫「每一輪都給 AI」與「掛在節點只是標出處」；每則的 ⋯ 選單：帶進這一輪、從這裡繼續談、到來源；新增預設「待確認」並帶 `sourceLineId` |
| 小改 | `NoteAddForm` 收 `sourceLineId`、`defaultSection`；`NoteItem` 收 ⋯ 選單；`RelationList`／`RelationsSection`／`GroupList` 收 `lineId` 只列這個節點的；`OpenBranchRequest` 收 `purpose`、`notice`；`DEFAULT_COMMANDS` 加 `focus.toggle`（⌘⇧F，可改鍵）；圖層開關可以帶自己的名稱 |
| 文字 | 專注模式的字在延遲載入的 `i18n/focus-messages.ts`；主字典只多三個（命令名稱、頂列「專注」） |

## 和規格、設計稿不同的地方

| 項目 | 規格／設計稿 | 實作 | 理由 |
|---|---|---|---|
| 收尾分組（S15） | 設計稿多畫了第二種呈現方式 | **沒做** | 規格的階段一沒有它；設計審查時已經發現它在 1440 會被面板蓋住欄位，要先決定欄位順序或平移規則 |
| 回覆中的節點（S9） | 設計稿用 lucide-static 的 `loader-2`（0.460 沒有這個名字，審查時查過） | 用專案 `lucide-react` 的 `Loader2`（同一個圖示），只在專注模式的地圖上取代種類圖示，名稱加「回覆中」；面板標頭寫「AI 回覆中」，手機分頁的「對話」有小點 | `lucide-react` 有這個名字，專案其他轉圈圖示也用它 |
| 紀要的勾選框 | 設計稿每則紀要都有 | 照現有規則，只有「待辦」有 | 改所有分區的完成語意是紀要頁的事，不在這一步 |
| 論證類型 | 規格寫「可改」 | 面板上只顯示 | 改它的控制在訊息上（D2），面板先不重做一份 |
| 順口問的「停車」 | 規格寫有 | 只有「記進紀要」 | 停車要那則回答的內容，面板先不讀 |
| 命令面板 | 「進入專注模式／離開專注模式」兩個字 | 一個命令「進入或離開專注模式」 | 命令的名稱是固定的 |
| 手機上的地圖 | 設計稿：沒有拉關聯、沒有多選 | 分頁模式連圖層也拿掉（只有平移、縮放、面板） | 規格 §4.1 寫的就是這三樣；圖層在 375 寬會佔掉一半高度 |
| 面板的「結論」 | 設計稿標「結論」 | 標「結論卡」 | 收尾的種類也叫「結論」，兩塊放在一起會重複 |

## 審查

寫完後請一個唯讀的 typescript-reviewer 看 `a75b43c..HEAD` 的 `web/`。成立並已修正：
1. 多選或拉關聯時，在節點上按 Enter（或雙擊）會直接進入那條線，而不是選取。現在這兩種模式下 Enter 與雙擊走點擊的路徑（有測試）。
2. 分岔點的光暈在訊息重抓時會先熄再亮。現在不先清掉，由新的 observer 一次回報。
3. 分隔線拖曳被取消（觸控中斷、失去 capture）時會卡在拖曳狀態，而且每次移動都寫一次 `localStorage`。現在拖曳中只更新畫面，放開、取消或失去 capture 時才存一次。
4. 窄寬切到「地圖」時，被蓋住的對話仍在 Tab 順序與無障礙樹裡。現在對話區在那段時間 `inert`。
5. N／F2 會從面板的選單（portal）冒泡上來，例如在選單裡打 n 會開新增紀要。現在只處理地圖區本身的按鍵。

記下但沒改：拖地圖的捲軸不會暫停跟隨（滾輪、拖曳畫布、縮放都會），之後支線清單重抓時可能把地圖捲回「你在這裡」。影響小，要改得分辨程式自己的捲動。

## 過程

- 第一次截圖發現三個問題並修好：紀要數量標記壓到節點第二行的字；地圖區 < 640 時面板從底部升起，但選取的節點被它蓋住（原本只避開右側）；聚焦子樹時「符合畫面」把往主線的路徑也算進去，縮到 50%。
- 全套 mock 有一次 6 個逾時：測試跑到一半時改了程式，Vite 熱更新讓頁面重載；`--last-failed` 重跑全過。另一次是每輪最先跑的 focus 測試等 Vite 冷編譯超過 5 秒（機器 load average 7–14），`focus.spec.ts` 加了第一次載入等 30 秒的 `open()`。
- e2e 第一輪 5 個失敗都是測試本身：頂列在 `<main>` 裡不是 banner 地標、「新對話」名稱對到多個按鈕、回覆數在頁面載入前就讀了。
