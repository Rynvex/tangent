package tangent // import "github.com/Rynvex/tangent"

Package tangent is the conversation-branch engine: it combines the store and the
domain logic with the host's hooks into the turn protocol, the branch operations
and background jobs, and publishes events after every commit. See docs/DESIGN.md
§6.

type AttachInput struct {
	SourceLineID    string
	AnchorMessageID string
	Purpose         string
	Kind            string
	Status          string
	Card            *domain.BranchCard
	ConfirmDeeper   bool
}
    AttachInput attaches another conversation of the tenant (SourceLineID,
    a main line) as a branch of a line (B20), the inverse of a detach.
    AnchorMessageID empty picks the newest anchorable message of the line dated
    no later than the source's start (else its newest). Purpose empty is the
    source's title (else its first question). Kind is investigate (the default)
    or alternative; Status open (the default) or merged, which needs Card (an
    empty question is the purpose) and leaves it on the line already delivered.

type Engine struct {
	// Has unexported fields.
}
    Engine runs conversations with branches over a host's pool.

func New(pool *pgxpool.Pool, opts ...Option) (*Engine, error)
    New builds an engine over the pool. The schema must be migrated
    (store.Migrate, and store.MigrateFeatures for a feature with migrations of
    its own, such as Search). It refuses limits that cannot work, features whose
    dependencies are missing and features whose migrations were not applied
    (checked against the database, within 10 seconds).

func (e *Engine) AcceptSuggestion(ctx context.Context, scope Scope, id string, body json.RawMessage, opts ...TxOption) (AcceptedSuggestion, error)
    AcceptSuggestion runs an open suggestion's action and marks it accepted
    in the same transaction. body is the kind's choice (for example which
    of two actions); a refused action leaves the suggestion open. InTx hooks
    receive the action's result: domain.Suggestion for a kind without one;
    store.PromotedBranch or store.SpunOff for rebalance.

func (e *Engine) AddMilestone(ctx context.Context, scope Scope, lineID string, in MilestoneInput, opts ...TxOption) (ChapterChange, error)
    AddMilestone marks a message as the start of a chapter. InTx hooks receive
    store.ChapterChange.

func (e *Engine) AnalyzeImport(ctx context.Context, scope Scope, in domain.ImportAnalyzeInput, r Runner) (domain.ImportAnalyzePlan, error)
    AnalyzeImport proposes how an import is organized
    (domain.ImportAnalyzePlan): which units (rounds or conversations)
    are one topic, even when other topics came between them, and which
    topics are chapters, branches or conversations of their own. in is
    checked first (invalid_input). With a runner the model is asked once
    (BuildImportAnalyzePrompt, at most ImportAnalyzeTimeout, the engine's
    default provider and model) and its plan is checked and repaired
    (ParseImportAnalyzeOutput, Source "model"); without one, or when the call
    fails, times out or its reply is not a usable plan, the deterministic
    analyzer answers (Source "heuristic") and the reason is logged without any
    of the conversation's text. Nothing is written.

func (e *Engine) AppendDelta(ctx context.Context, turnID string, d domain.Delta) error
    AppendDelta buffers a streamed piece of a pending turn's reply and
    publishes it as message.delta. The turn is looked up once and remembered.
    Text is filtered by line: a line that starts with a protocol marker is
    never streamed, and the start of a line is held until it cannot become
    one (CompleteTurn flushes the rest). Every DefaultPartialInterval or
    DefaultPartialBytes of text (WithPartialFlush) the text streamed so far is
    saved on the pending message with meta.streamSeq.

    An Engine built WithDeltaSink forwards the delta to its sink instead (a
    worker process); the API process's AppendDelta is where such deltas arrive.

    Runner side only: the bare turn id carries no tenant check, so this must
    never be reachable by clients (httpapi does not route it).

func (e *Engine) AppendSystemMessage(ctx context.Context, scope Scope, lineID string, n SystemNotice, opts ...TxOption) (AppendedSystemMessage, error)
    AppendSystemMessage appends a host system message to a line: under the
    line's lock, after everything the line holds (also while a turn is pending:
    the notice then follows the pending reply, and that turn's prompt,
    built already, does not show it). An archived line, an ended branch (or
    one below an ended branch) and a line that is gone refuse it; blank text
    is invalid_input. message.created and line.updated are published after the
    commit; a skipped repeat writes and publishes nothing and its hooks do not
    run. InTx hooks receive store.AppendedSystemMessage.

func (e *Engine) ApplyNoteChanges(ctx context.Context, scope Scope, lineID string, changes []domain.NoteChange, opts ...TxOption) (NotesWrite, error)
    ApplyNoteChanges adds or supersedes notes in one transaction. InTx hooks
    receive store.NotesWrite.

func (e *Engine) ArchiveTree(ctx context.Context, scope Scope, lineID string, archived bool, opts ...TxOption) ([]domain.LineView, error)
    ArchiveTree archives (or unarchives) a whole conversation; the main line
    comes first in the result. InTx hooks receive []domain.LineView.

func (e *Engine) AttachLine(ctx context.Context, scope Scope, lineID string, in AttachInput, opts ...TxOption) (AttachedLine, error)
    AttachLine hangs the source conversation, with its whole tree, on the line:
    the source keeps its messages (and their seq) and becomes a branch line (its
    folder, tags and origin capsule go), its branches go one level deeper per
    the new branch's depth, and its notes, memos, seeds, leaves, chapter cuts,
    suggestions and groups move to the line's conversation (its goal goes).
    The branch limits count the source's tree. With a card, the branch is
    merged at once and, while leaf is on, the card is written as its confirmed
    leaf. No feature hook runs and no job is started. InTx hooks receive
    store.AttachedLine.

func (e *Engine) BeginTurn(ctx context.Context, scope Scope, lineID string, in TurnInput, opts ...TxOption) (Turn, error)
    BeginTurn starts a turn: the TurnGate is asked first (outside the
    transaction), then the operator's message and a pending reply are stored
    and the line goes thinking, under the line's lock; the prompt is built
    after the commit. If the prompt cannot be built the turn is failed at once.
    InTx hooks receive store.BegunTurn.

func (e *Engine) CancelTurn(ctx context.Context, scope Scope, lineID string, opts ...TxOption) (CancelledTurn, error)
    CancelTurn ends the line's pending turn, keeping the text streamed so far
    (complete for a run of this process, else what the delta buffer holds), and
    stops its run when this process runs it. Only the turn that was pending when
    the call started is cancelled: if it finished and another began meanwhile,
    nothing changes. Without a pending turn nothing is written (and the hooks do
    not run). InTx hooks receive store.CancelledTurn.

func (e *Engine) Capabilities(ctx context.Context, scope Scope) ([]Capability, error)
    Capabilities lists every built-in feature with whether it is on for the
    scope and, where it has one, its effective mode.

func (e *Engine) CombineBranches(ctx context.Context, scope Scope, parentLineID string, in CombineInput, opts ...TxOption) (CombinedBranches, error)
    CombineBranches combines open branches of one parent into a new branch
    anchored on the newest of their anchors, and their open children are
    re-hung on it (keeping the message they forked from as their anchor). Its
    pack is the parent's background at that anchor plus each branch's purpose,
    leaf and newest messages, and what the operator settled. The old branches
    are discarded (open suggestions about them expire) in the same transaction.
    InTx hooks receive store.CombinedBranches.

func (e *Engine) CompleteTurn(ctx context.Context, turnID string, r TurnResult, opts ...TxOption) (CompletedTurn, error)
    CompleteTurn finishes a pending turn, once: a turn that is no longer pending
    returns ErrTurnNotPending. The scope is the turn's own (tenant and the
    actor who began it). A successful reply passes the features' reply filters;
    OnTurnCompleted hooks (and OnBranchClosed for an aside the answer ended)
    run in the transaction, AfterCommit hooks after it. Notices that are too
    many, too long or carry host data that is not a JSON object are refused
    (invalid_input, too_long) and the turn stays pending.

    Runner side only: the bare turn id carries no tenant check, so this must
    never be reachable by clients (httpapi does not route it). InTx hooks
    receive store.CompletedTurn.

func (e *Engine) Converge(ctx context.Context, scope Scope, parentLineID string, in ConvergeInput, opts ...TxOption) (ConvergeStarted, error)
    Converge compares 2–5 open, non-aside branches of the line (the parent): a
    drafting comparison and its converge job, which fills the matrix. Refusals:
    invalid_comparison (count, another parent, an aside, not a branch),
    branch_closed, archived; criteria over the limits (invalid_input, too_long).
    InTx hooks receive store.ComparisonWrite.

func (e *Engine) ImportLine(ctx context.Context, scope Scope, in ImportInput, opts ...TxOption) (ImportedLine, error)
    ImportLine writes an imported conversation as a new main line with
    its branches, in one transaction and without calling a model:
    the input is checked and cleaned first (domain.PlanImport; the title,
    provider and model like CreateLine's, the title taken from the first
    operator message when empty), each branch's pack is built from the imported
    messages up to its anchor like a new branch's, and the branches are open,
    discarded or merged as asked (origin import). Imported messages carry no
    usage or model. B19: the source's dates are kept (every line and message
    is otherwise dated at the import), chapter cuts are written as milestones,
    and a merged branch leaves its card on the main line right after its anchor,
    already delivered (with the leaf feature on, the card is also its confirmed
    leaf). No job is started and no feature hook runs: an import is history,
    not activity. Events after the commit: line.created for the main line, then
    for each branch line.created and branch.changed{created}, then leaf.changed
    for each leaf written and, with the chapters feature on and a cut written,
    chapters.changed. InTx hooks receive store.ImportedLine.

    StartDiverge starts a diverge job: Count (2–5) directions from the anchor,
    a finished operator or assistant message of the line (anchor_not_found),
    with room for that many more open branches under it (branch_limit).
    Its branches are opened when the job finishes. InTx hooks receive store.Job.

    StartDraft starts drafting the branch's conclusion card: the branch is
    marked drafting (it takes no turns until the draft ends) and the card_draft
    job is returned for the host to run. InTx hooks receive store.DraftClaim.

    StartLeafDraft starts a leaf_draft job for a branch (any mode, the operator
    asked); a pending draft of the branch is superseded. The draft is written
    when the job finishes, unless the operator's leaf is there. InTx hooks
    receive store.Job.

func (e *Engine) StartSummary(ctx context.Context, scope Scope, lineID string, opts ...TxOption) (Job, error)
    StartSummary starts a rolling summary of the line's messages after its
    summary cursor (up to the first undelivered card); a pending summary of the
    line is superseded. InTx hooks receive store.Job.

func (e *Engine) StreamSince(ctx context.Context, scope Scope, lineID string, afterSeq int64) (DeltaTail, error)
    StreamSince returns the buffered deltas of a line after afterSeq (a
    reconnecting client catches up with it). The buffer is per process and
    bounded; Truncated says deltas after the cursor are gone and the client must
    reload the messages.

func (e *Engine) SummarizeGroup(ctx context.Context, scope Scope, groupID string, opts ...TxOption) (Job, error)
    SummarizeGroup starts a group_summary job for an active group (any mode:
    the operator asked); a summary started before it no longer writes. InTx
    hooks receive store.GroupSummaryClaim.

func (e *Engine) SupersedeMemory(ctx context.Context, scope Scope, memoryID string, in domain.MemoryInput, opts ...TxOption) (SupersededMemories, error)
    SupersedeMemory replaces an active memory by the operator's new one; the
    kind, importance and validity default to the old one's, the source is the
    old one's. Nothing is deleted. InTx hooks receive store.SupersededMemories.

func (e *Engine) SupersedeNote(ctx context.Context, scope Scope, lineID, noteID string, in NoteInput, opts ...TxOption) (NotesWrite, error)
    SupersedeNote replaces a note with a new one; the old one is kept and points
    at its successor. An empty section keeps the old note's. InTx hooks receive
    store.NotesWrite.

func (e *Engine) TagMessage(ctx context.Context, scope Scope, messageID, kind string, opts ...TxOption) (domain.Message, error)
    TagMessage writes the operator's confirmed tag (question, idea, pro,
    con or decision) on a finished operator or assistant message; it replaces
    any tag. message.updated follows when it changed. InTx hooks receive
    store.TaggedMessage.

func (e *Engine) TenantOrganization(ctx context.Context, scope Scope) (domain.TenantOrganization, error)
    TenantOrganization returns the tenant's folders (active and archived main
    lines counted apart) and the tags of its unarchived main lines with their
    counts (B18.1), over every main line rather than one page of ListLines.
    Read-only.

func (e *Engine) TurnPending(ctx context.Context, scope Scope, turnID string) (bool, error)
    TurnPending reports whether the turn is still pending for the scope's
    tenant: false once it was completed, cancelled or failed as stale (and for
    an unknown id or another tenant's turn). A worker that cannot observe the
    API process's events asks it to learn about a cancel.

func (e *Engine) UntagMessage(ctx context.Context, scope Scope, messageID string, opts ...TxOption) (domain.Message, error)
    UntagMessage removes a message's tag (nothing changes without one). InTx
    hooks receive store.TaggedMessage.

func (e *Engine) UpdateBranchCard(ctx context.Context, scope Scope, lineID string, card domain.BranchCard, opts ...TxOption) (UpdatedCard, error)
    UpdateBranchCard replaces the conclusion card of a merged branch (B17).
    The card is checked as a merge checks it (invalid_card with every problem),
    rendered onto the same card message and marked undelivered, so the next turn
    of the line that holds it carries the edited card once, in the card notice.
    The branch's conclusion line follows, and so does its leaf while it is still
    the one the merge wrote from the card and the leaf feature is on. Nothing
    else derived from the old card is rewritten (memories, a rolling summary,
    a group summary, the pack of a branch opened on the card). It publishes
    message.updated, branch.changed{merged} and, when the leaf followed,
    leaf.changed. InTx hooks receive store.UpdatedCard.

func (e *Engine) UpdateFold(ctx context.Context, scope Scope, foldID, summary string, opts ...TxOption) (domain.Fold, error)
    UpdateFold writes the operator's summary on a fold (any status but removed):
    it becomes active and no longer counts as drafted by a model; a drafting
    fold's job no longer writes. Refusals: an empty summary (invalid_input),
    one over the limit (too_long), fold_not_found, archived. InTx hooks receive
    store.FoldWrite.

    UpdateLine edits the title, provider, model or host data of a line. InTx
    hooks receive domain.LineView.

func (e *Engine) UpdateMemo(ctx context.Context, scope Scope, memoID, text string, opts ...TxOption) (domain.Memo, error)
    UpdateMemo replaces a memo's text. InTx hooks receive domain.Memo.

func (e *Engine) UpdateMemory(ctx context.Context, scope Scope, memoryID string, patch MemoryPatch, opts ...TxOption) (domain.Memory, error)
    UpdateMemory applies a patch to an active memory (memory_superseded for a
    superseded one). InTx hooks receive domain.Memory.

func (e *Engine) UpdateNote(ctx context.Context, scope Scope, lineID, noteID string, patch NotePatch, opts ...TxOption) (NoteUpdate, error)
    UpdateNote changes the text, section or status of a note. InTx hooks receive
    store.NoteUpdate.

func (e *Engine) UpdateRelation(ctx context.Context, scope Scope, lineID, relationID, label string, opts ...TxOption) (RelationChange, error)
    UpdateRelation changes the label of a relation one of whose ends is in the
    line's conversation and keeps its kind; see EditRelation. InTx hooks receive
    store.RelationChange.

type Feature interface {
	// Name is the feature's stable name (for example "notes").
	Name() string
	// Requires names the features it cannot work without.
	Requires() []string
	// AI reports whether the feature calls a model (and so has a Mode).
	AI() bool

	// Has unexported methods.
}
    Feature is one built-in optional module. The set is closed: only this
    package implements it (Notes, Chapters, Aside, Summary, CardDraft,
    BranchSuggest, Search, Leaf, Parking, Spinoff, Rebalance, Goal,
    Relations, OpenLoops, Fisheye, Group, Ibis, Fold, Diverge, Memory, Memo,
    and SuggestionProbe for tests).

func AllFeatures() []Feature
    AllFeatures is every first-batch feature: notes, chapters, asides and card
    drafts on, summaries suggested when due, branch suggestions.

func Aside() Feature
    Aside is the one-question branch (kind aside): answered once, then ended,
    and purged with its messages after Limits.Branch.AsideRetention. Off:
    opening an aside (or moving into one) returns feature_disabled and Maintain
    purges nothing; existing asides are kept.

func BranchSuggest(mode Mode, opts ...FeatureOption) Feature
    BranchSuggest lets the model propose side branches: the prompt carries
    the [BRANCH-SUGGEST] rule and the reply's suggestion lines are parsed
    into meta.suggestions, which the operator can accept (CreateBranch with
    SuggestionMessageID). Suggest and Auto behave alike (a suggestion is never
    acted on by itself); Manual carries no rule and parses nothing, but stored
    suggestions can still be accepted. Off: no rule, no parsing, and accepting a
    suggestion returns feature_disabled.

func CardDraft(opts ...FeatureOption) Feature
    CardDraft drafts a branch's conclusion card with a tool-free job;
    the operator edits and confirms it before merging. It is on or off (DESIGN
    §12): clients decide when to call StartDraft. Off: StartDraft returns
    feature_disabled and cards are written by hand.

func Chapters() Feature
    Chapters are computed when read: idle gaps, the topic cuts summaries record,
    and milestones the operator sets. On the main line, once the current
    chapter holds domain.ChapterCutMinMessages finished messages, a turn's
    prompt also allows a [CHAPTER] line; the title it carries is recorded as a
    topic cut on that turn's operator message. A main line's first-turn [TOPIC]
    title names the first chapter the same way. Off: nothing is recorded (the
    marker lines are still removed from replies) and the chapter calls return
    feature_disabled; stored cuts are kept.

func Diverge(mode Mode, opts ...FeatureOption) Feature
    Diverge explores and settles alternatives (DESIGN §12 B10):
    diverging asks a model for N (2–5) distinct directions from a message,
    and each becomes a sibling branch hanging on it (kind alternative,
    origin diverge; its pack names its direction and the others). Converging
    compares open sibling branches in a criteria × options matrix with scores,
    reasons and a recommendation (a converge job → a comparison); deciding,
    in one transaction, gives the chosen branch a decision leaf and discards the
    other compared branches with a dead-end leaf. Every step is the operator's
    (any mode; nothing happens by itself). Needs leaf. Off: the calls return
    feature_disabled; comparisons are kept.

func Fisheye() Feature
    Fisheye replaces the default history of a prompt with a fisheye view (DESIGN
    §12 B9): every message of the line and every other branch of the tree gets
    a score (its head start minus its distance) and a level: full, summary (one
    condensed line, or covered by the rolling summary), leaf_only (another
    branch's leaf in the "other branches' conclusions" block) or hidden,
    within what the shared budget left for the history. Head starts: a pin,
    a reference from a note or a card, being a card, a confirmed decision tag
    (while ibis is on); for branches, the leaf's kind. The line's own path (it
    and its ancestors) is carried by its pack, not by this. PreviewTurn reports
    every item. No model, on or off; needs leaf. Off: the default history.

func Fold(mode Mode, opts ...FeatureOption) Feature
    Fold folds a stretch of a line into one summary (DESIGN §12 B10):
    the messages stay where they are, but every later prompt of the line
    carries the summary in their place (applied before the HistorySelector,
    so the fisheye weighs the fold as one entry). The operator folds a range
    with a summary of their own or asks a model to draft one (a fold_summary
    job, any mode); PreviewTurn lists the folds it applied. Folds follow their
    messages when a move or a promotion takes them to another line, and a fold
    whose ends were split no longer applies. Suggest (Auto alike: a fold changes
    what the model sees, so nothing is folded by itself) also summarizes,
    every Limits.Fold.SuggestEvery replies of a line, its oldest closed chapter
    worth folding (fold_suggest → the inbox; a dismissed chapter is not proposed
    again). Off: the fold calls return feature_disabled and prompts carry every
    message; stored folds are kept.

func Goal(mode Mode, opts ...FeatureOption) Feature
    Goal is the conversation's goal (DESIGN §12 B9): one line per conversation,
    carried by every prompt of its tree right after the rules (a stable block).
    The operator writes it, or asks the model to propose one (ProposeGoal, any
    mode). Suggest and Auto also propose one by themselves after the main line's
    second reply when there is none, and check every Limits.Goal.DriftEvery
    main-line replies whether the conversation drifted from it (a drift
    suggestion: open a branch or an aside there). A proposal waits in the inbox;
    Auto writes it as the goal instead (never over a goal that is there,
    unless the operator asked). Manual: the goal and the button only. Off:
    the goal calls return feature_disabled and prompts carry no goal; a stored
    goal is kept.

func Group(mode Mode, opts ...FeatureOption) Feature
    Group circles branches together (DESIGN §12 B9): a group of ended branches
    gets one shared summary (a group_summary job, started when the group is
    made or asked again) that stands for their leaves in the fisheye context;
    open sibling branches can be combined into one new branch (origin merge)
    that carries their background, the old ones discarded and pointing at it.
    Either may settle conflicts between the branches' claims (adopt one side, or
    keep both as a note to confirm). Suggest (Auto alike: nothing is grouped by
    itself) also asks a cheap model, whenever a branch ends, to propose groups
    and their conflicts (group_suggest → the inbox). Manual: by hand only. Needs
    leaf. Off: the group calls return feature_disabled; stored groups are kept.

func Ibis(mode Mode, opts ...FeatureOption) Feature
    Ibis marks messages with their role in the argument (DESIGN §12 B10,
    IBIS): question, idea, pro, con or decision. The operator tags any finished
    operator or assistant message (TagMessage, any mode). Suggest and Auto
    also ask a cheap model, every Limits.Ibis.Every (3) replies of a line that
    is not an aside, to tag its newest untagged messages (one ibis_tag job,
    at most Limits.Ibis.BatchMax after the last finished job): Suggest writes
    them as drafts the operator confirms by tagging, Auto as confirmed tags.
    A model never replaces a tag, and the operator's tags are the operator's.
    Messages and the outline (the anchor's tag) carry tags; with the fisheye
    on, a confirmed decision is a head start. Off: the tag calls return
    feature_disabled and no job runs; stored tags stay and still show.

func Leaf(mode Mode, opts ...FeatureOption) Feature
    Leaf is the closing note of a branch (DESIGN §12 B8): a merge writes a
    conclusion leaf from its card in the same transaction; a discard may
    carry a dead-end leaf; the operator writes or confirms one at any time.
    Suggest and Auto also draft one with a job when a branch is discarded
    without a leaf and for the previous main line of a promotion (Suggest:
    a draft for the operator to confirm; Auto: confirmed, marked aiDrafted).
    Manual drafts only when asked (StartLeafDraft). A leaf never enters a turn
    prompt. Off: the leaf calls and a discard's leaf return feature_disabled;
    stored leaves are kept (the outline still shows them).

func Memo() Feature
    Memo keeps notes on a node that never go to the AI (DESIGN §12.10, B13):
    it registers no ContextProvider, so a memo is in no prompt, no turn preview
    and no job. Memos are not private: every reader of a conversation reads its
    memos. Off: the memo calls return feature_disabled; stored memos are kept.

func Memory(mode Mode, cfg MemoryConfig, opts ...FeatureOption) Feature
    Memory keeps what a tenant's conversations settled across conversations
    (DESIGN §12 B10): memories (fact, decision, preference, lesson) with their
    sources, never deleted, only superseded. Recall ranks them by relevance
    (the Embedder's cosine similarity) × recency × importance: every turn's
    prompt carries the best few that fit the budget (unless NoTurnRecall;
    visible in PreviewTurn only), and SearchMemories serves the offers at a
    new conversation or branch. Suggest and Auto extract memories with a cheap
    model after a merge, a confirmed leaf or a decided note (memory_extract:
    Suggest proposes them in the inbox, Auto writes them), and the maintenance
    loop looks for near-duplicate memories (memory_consolidate → the inbox:
    merge them, or a conflict to settle). Manual: the operator's memories
    and recall only. Needs notes, the vector extension and its migration
    (store.MigrateFeatures(ctx, pool, "memory")). Off: the calls return
    feature_disabled and prompts carry no memories; stored memories are kept.

func Notes() Feature
    Notes is the notes page of a conversation (decided / fact / to_confirm
    / todo): carried by every turn, written with merges or on its own. Off:
    the prompt carries no notes, merge noteChanges and the notes calls return
    feature_disabled; stored notes are kept.

func OpenLoops() Feature
    OpenLoops lists what conversations left unfinished (DESIGN §12 B9):
    open branches idle longer than N days (default Limits.OpenLoops.StaleAfter,
    3 days), notes to confirm (while notes is on), open seeds (while parking is
    on) and open suggestions (of the features that are on), for the whole tenant
    or one conversation. Read-only, no model and no table of its own; the items
    are acted on with the existing calls (discard, notes, seeds, the inbox).
    Off: OpenLoops returns feature_disabled.

func Parking() Feature
    Parking keeps thoughts for later (DESIGN §12 B8): a seed costs no tokens
    (no branch, no model call, never in a prompt). A seed is expanded into a
    branch (origin seed), written into the notes (needs notes) or dropped;
    each ends it for good. Off: the seed calls return feature_disabled; stored
    seeds are kept.

func Rebalance(mode Mode, opts ...FeatureOption) Feature
    Rebalance hints when a branch has taken over the conversation (DESIGN
    §12 B8): after a turn of an open branch whose replies since the fork
    reach Limits.Rebalance (at least MinBranchTurns and ShareFactor times
    the parent's, or the tree's last RecentTurns replies all its), it raises
    a promote_or_spinoff suggestion about the branch. Accepting promotes
    it (top-level branches only) or spins it off (detach; needs spinoff);
    dismissing ("keep as is") is final for that branch. Suggest and Auto behave
    alike (nothing changes without the operator); Manual raises nothing.
    Needs leaf (the previous main line of a promotion gets a leaf).

func Relations(mode Mode, opts ...FeatureOption) Feature
    Relations draws labelled lines between two places (a line, or a message
    on it) of the tenant's conversations, in one tree or across two (DESIGN
    §12 B9); they are links of kind relation, listed by /links too. Suggest
    (and Auto, which behaves alike: a relation is drawn only when the operator
    accepts it) asks a cheap model, when a branch is merged or discarded, which
    other branches of the tree it relates to, and raises each as a relation
    suggestion. Manual: drawn by hand only. Off: the relation calls return
    feature_disabled; stored relations are kept.

func Search() Feature
    Search finds text across a tenant's conversations: main-line titles,
    branch purposes and finished operator and assistant messages. It needs the
    pg_trgm extension and its own migration: run store.MigrateFeatures(ctx,
    pool, "search") before New (New refuses otherwise). Off: Search returns
    feature_disabled.

func Spinoff() Feature
    Spinoff makes a part of a conversation a new one (DESIGN §12 B8): detach
    turns an open branch, with everything below it, into a main line of its own;
    fresh starts a new main line from any finished message. The new main line
    starts every prompt with its origin capsule (the branch's pack, or the
    path to the message, and the branch's leaf while leaf is on); the source
    line keeps a marker and both are linked. Off: Spinoff and ListLinks return
    feature_disabled; spun-off lines keep their capsule.

func SuggestionProbe() Feature
    SuggestionProbe is for tests, smoke runs and e2e only, never a product
    feature: it is not in AllFeatures nor the catalog, and /capabilities
    does not list it (it only turns the suggestion inbox on). After a turn
    whose reply contains ProbeDirective it raises a "probe" suggestion about
    the turn's line (ProbeDirectivePermanent: a "probe_permanent" one, whose
    dismissal is final). Accepting one does nothing besides accepting it; its
    result is {"accepted": true}. The fake runner echoes the operator's message,
    so sending a directive raises one.

func Summary(mode Mode, opts ...FeatureOption) Feature
    Summary is the rolling summary of a line: it stands for the history
    it covers in every prompt and in the packs of new branches. Manual:
    only StartSummary; Suggest: CompletedTurn.SummaryDue once the unsummarized
    history passes the trigger; Auto: the summary job is started then and
    returned in CompletedTurn.Jobs. Off: prompts and packs carry no summary
    (history is cut at HistoryScan) and StartSummary returns feature_disabled;
    stored summaries are kept.

    process whose deltas the API process numbers.

type RunnerDispatcher struct {
	// Has unexported fields.
}
    RunnerDispatcher runs each turn and job on its own goroutine with a Runner,
    under a timeout and an optional concurrency bound, and always writes the
    outcome back: a runner error, panic or timeout fails the turn or job. A run
    outlives the context it was dispatched with; only Shutdown or Close stops
    it. Jobs a completed turn started (CompletedTurn.Jobs) are dispatched too.

func NewRunnerDispatcher(e *Engine, r Runner, opts ...DispatcherOption) *RunnerDispatcher
    NewRunnerDispatcher runs work in this process with r.

func (d *RunnerDispatcher) Close() error
    Close stops taking work, cancels every run and waits for the write-backs.

func (d *RunnerDispatcher) DispatchJob(ctx context.Context, j Job) error
    DispatchJob starts running the job and returns at once.

func (d *RunnerDispatcher) DispatchTurn(ctx context.Context, t Turn) error
    DispatchTurn starts running the turn and returns at once.

func (d *RunnerDispatcher) InFlight() int
    InFlight is how many turns and jobs the dispatcher holds: running or waiting
    for a slot.

func (d *RunnerDispatcher) RunOnce(ctx context.Context, req RunRequest) (RunResult, error)
    RunOnce runs one request now and returns its result, nothing stored
    (B22's import analysis): it counts against WithMaxQueue and WithMaxOnce
    (ErrDispatcherBusy beyond either) and waits for a WithMaxConcurrent slot
    like any run; Shutdown waits for it and Close cancels it. A runner panic is
    an error.

func (d *RunnerDispatcher) Shutdown(ctx context.Context) error
    Shutdown stops taking work and waits for the runs to finish. When ctx ends
    first, the runs are cancelled (they write their failure back) and Shutdown
    waits for those write-backs, returning ctx's error.

func (d *RunnerDispatcher) Wait()
    Wait blocks until every dispatched run has written its outcome back (tests).
    Use Shutdown to stop.

	Content    string
	Error      string
	Usage      *domain.Usage
	DurationMs int64
	Provider   string
	Model      string
	Notices    []SystemNotice
}
    TurnResult is what running a turn produced. A non-empty Error fails the
    turn; it is stored and published, so it must be a text meant for the
    operator, never a raw upstream error. Provider and Model, when set,
    name what actually ran. Notices are host system messages written right after
    the reply, in order, in the same transaction (a failed reply gets them too;
    blank ones are left out, at most 16).

type TurnRetrying struct {
	TurnID      string    `json:"turnId"`
	Attempt     int       `json:"attempt"`
	MaxAttempts int       `json:"maxAttempts"`
	NextRetryAt time.Time `json:"nextRetryAt"`
}
    TurnRetrying is the data of turn.retrying: the runner hit a 429 / 5xx and
    tries again at NextRetryAt.

type TxHook = store.TxHook
    TxHook runs inside a write's transaction before the commit; an error rolls
    the whole write back. See store.TxHook.

type TxOption func(*txOptions)
    TxOption adds to a write's transaction.

func InTx(h TxHook) TxOption
    InTx runs h inside the write's transaction, after the library's own writes
    (DeleteTree: before the rows go) and before the commit.

type UpdatedCard = store.UpdatedCard
    UpdatedCard is what a card edit changed.
