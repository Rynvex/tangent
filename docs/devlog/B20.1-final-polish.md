# B20.1 — B20 + F14.1 + F15 收尾（5 項體驗與併發修正）

日期：2026-11-03

## 1. 做了什麼

1. **結論卡（`kind = branch_card`）不觸發時間空檔章節**
   - [`domain/chapters.go`](../../domain/chapters.go)：`collectBoundaries` 在挑 `idle` 切點時加上 `!messages[i].IsCard`。把既有對話併進一則較舊的對話（`POST /lines/{id}/attach`）或合併支線（`MergeBranch`）時，結論卡的 `created_at` 是當下時間（`NOW()`），不再因為與前一則訊息相隔超過 30 分鐘而在結論卡正前方多切一個只有 1 張卡片的閒置章節。
   - [`web/packages/client/src/testing/mock-chapters.ts`](../../web/packages/client/src/testing/mock-chapters.ts)：同步加上 `messages[i]!.kind !== "branch_card"`。
   - 測試：[`domain/chapters_test.go`](../../domain/chapters_test.go)、[`web/packages/client/src/testing/mock-chapters.test.ts`](../../web/packages/client/src/testing/mock-chapters.test.ts)。
2. **`store/chapters.go`、`store/relations.go`、`store/seeds.go`、`store/groups.go` 補齊上鎖後確認主線**
   - [`store/chapters.go`](../../store/chapters.go)：`RecordTopicCut` 改用 `s.lockLine(ctx, q, tenant, lineID)` 先鎖 `line` 再讀 `rootOf` 寫入 `tangent_milestone`，避免併發 `AttachLine` 時切點落到舊 `root_line_id`。
   - [`store/relations.go`](../../store/relations.go)：`lockRelationEnds` 與 `lockRelation` 在依序鎖住兩端 `root` 後，重新確認 `s.rootOf(ctx, q, here.line) == here.root`；若被併發 `AttachLine` 搬移則回傳 `errBranchMoved` 重試。
   - [`store/seeds.go`](../../store/seeds.go)、[`store/seed_end.go`](../../store/seed_end.go)：`lockOpenSeed` 鎖住種子列後確認 `row.RootLineID == rootID`，避免併發 `DetachBranch`／`AttachLine` 搬移時寫到舊樹。
   - [`store/groups.go`](../../store/groups.go)、[`store/group_summary.go`](../../store/group_summary.go)：`lockActiveGroup` 與 `FinishGroupSummary` 改用 `lockRootOf` 並在鎖住群組列後確認 `row.RootLineID == root.ID`。
   - 同時確認 `tags.go`、`folds.go`、`pins.go`、`comparisons.go` 皆已先鎖 `line.ID`（或 `lockParent`）才讀 `rootOf`，而 `AttachLine` 會鎖住來源樹所有 `line`，不會發生未鎖競態。
3. **消除批次匯入時重複的 `GET /lines` 與 `GET /lines/organization` 請求風暴**
   - [`web/packages/react/src/data/event-sync.ts`](../../web/packages/react/src/data/event-sync.ts)：`case "line.created"` 原本先呼叫 `onLineUpdated(qc, payload.line)`（已 invalidate `lineLists` 與 `lineOrganization`），底下又再 invalidate 一次；拿掉重複呼叫，每次 `line.created` 只 invalidate 一次。
   - [`web/apps/demo/src/frame/f14/use-assembly-import.ts`](../../web/apps/demo/src/frame/f14/use-assembly-import.ts)：`adapter.importConversation` 改為直接呼叫 `client.importConversation` 並以 `queryClient.setQueryData` 寫入單篇快取，等整批匯入完成後在 `settle` 裡統一 invalidate 一次 `lineLists` 與 `lineOrganization`。
4. **提示列（Toast）Z-index 與 375px 窄螢幕換行修正**
   - [`web/apps/demo/src/shell.tsx`](../../web/apps/demo/src/shell.tsx)：底部提示列從 `z-50` 改為 `z-40`，避免蓋住對話框（`z-50`）底部的「取消／確認」按鈕；提示文字從 `whitespace-nowrap` 改為 `max-w-full flex-wrap`（動作按鈕保留 `shrink-0 whitespace-nowrap`），375px 手機寬度不再水平溢出。
5. **「併入其他既有對話…」對話挑選器加上標題篩選框**
   - [`web/packages/react/src/f13/attach-line-dialog.tsx`](../../web/packages/react/src/f13/attach-line-dialog.tsx)、[`web/packages/react/src/i18n/attach-messages.ts`](../../web/packages/react/src/i18n/attach-messages.ts)：當從拆解面板底部點「併入其他既有對話…」（`source === null`）且可選主線超過 3 篇時，在下拉選單上方顯示「篩選對話標題」（`Filter conversations`）輸入框，可依標題即時過濾候選對話。
   - 測試：[`web/packages/react/src/f13/attach.test.tsx`](../../web/packages/react/src/f13/attach.test.tsx)。
6. **匯入對話框自動分析通用 JSON 結構與清理網頁擷取雜訊**
   - [`web/packages/client/src/import-parsers.ts`](../../web/packages/client/src/import-parsers.ts)：除了 ChatGPT、Claude、Gemini Takeout／API 與 Tangent 備份外，新增通用 JSON 對話結構分析器（`analyzeGenericJson`），自動遞迴辨識 `dialogue`、`messages`、`turns`、`sessions`、`conversations` 等訊息陣列、問答配對物件（`prompt`/`response`、`question`/`answer`）、標題／資料夾／時間欄位（如 `projectName`、`timestamp`），並容忍尾隨逗號與 JSONL；超過 200 則時自動依提問邊界分段；同時自動清除瀏覽器擴充功能擷取 Gemini 網頁時帶入的「你說了 …」（含重複一次的提問文字）、「Gemini 說了…」與「編輯影像」尾綴。
   - 測試：[`web/packages/client/src/import-parsers.test.ts`](../../web/packages/client/src/import-parsers.test.ts)。
