## 做了什麼

- **後端**：`UpdateCardMessage` 在卡片訊息的 `meta` 寫 `editedAt`（`clock_timestamp()` 轉 UTC，微秒），`delivered` 照舊拿掉；`MarkCardsDelivered` 只改 `delivered`，`editedAt` 保留。三個大綱查詢投影 `card_edited_at`，`BranchView.CardEditedAt` 帶出同一個時間。兩個欄位都是 `*time.Time` + `omitempty`。
- **前端**：
  - `cardState(card)` 只看 `meta.delivered` 與 `meta.editedAt`。
  - 「前提已更新」：來源支線的 `cardEditedAt` 晚於追問支線的 `createdAt`（兩者都是資料庫時鐘）；只標進行中與已帶回的追問。理由 id 是 `card:<anchorMessageId>:<cardEditedAt>`，「知道了」只忽略那一次，再編輯會重新提醒。
  - F12 的 `localStorage` 編輯紀錄（`data/card-edits.ts`、`useCardEdits`、`tangent:card-edits:v2`、`storage` 監聽）整個刪掉。「知道了」的忽略紀錄（`tangent:stale-dismissed:v1`）照舊存在這台裝置。
  - mock 的卡片編輯同時寫兩個欄位，時間一定晚於樹裡所有支線的 `createdAt` 與上一次編輯（mock 時鐘停住也一樣）。
  - 測試在沒有 `localStorage` 的情況下驗證：卡片自帶 `editedAt` 就顯示「已修改・下一輪帶入」、送達後顯示已送達；編輯前開的追問支線有「前提已更新」，編輯後開的沒有；e2e 存檔後檢查膠囊文字，且 `localStorage` 沒有 `tangent:card-edits*`。
- **文件**：`docs/API.md`（Message.meta、BranchView、PATCH card）、`docs/DESIGN.md` 與 `docs/design/DECISIONS_LOG.md`（決定一列）、B17 devlog 追記、F12 devlog 的「建議的後續」註明已完成。

## 和工單不同的地方

1. **大綱查詢用 `LEFT JOIN` + `CASE`，不是子查詢。** 工單的 `(SELECT (meta->>'editedAt')::timestamptz …)` 被 sqlc 1.30 推成 NOT NULL 的 `time.Time`，遇到 NULL 會掃描失敗；NULLIF、max()、LATERAL 也都推錯。改成 `LEFT JOIN tangent_message cm` 加 `CASE WHEN … IS NOT NULL THEN …::timestamptz END`，sqlc 給 `interface{}`，`store/convert.go` 的 `anyTimePtr` 轉成 UTC 的 `*time.Time`。
2. **`cardState` 沒有 `edited` 參數。** 拿掉 `localStorage` 紀錄後它沒有來源，留著只是死碼。
3. **`followUpsOfEditedCards` 換成 `editedCardSource(branch, outline)`**，訊息列表直接呼叫 `cardEditReasons`。
4. **時間比到微秒（`isoMicros`），不是 `Date.parse`。** `Date.parse` 只到毫秒，同一毫秒內先開追問、再編輯卡片會被當成同時而漏標。
